### 4.3. Deployment View

#### 4.3.1. Назначение представления

Deployment View описывает физическое размещение компонентов SQL Trainer во внутренней инфраструктуре компании: какие узлы и подсети задействованы, где находятся backend-сервисы, базы данных, SSO, а также через какие точки и по каким протоколам проходят запросы пользователей.

Представление используется DevOps, эксплуатацией и ИБ для:

* понимания среды размещения (VPN, периметр, кластер приложений, базы данных, зона SSO);
* анализа сетевых потоков и портов;
* оценки точек отказа и зон ответственности.

---

#### 4.3.2. Основные элементы среды развёртывания

В рамках учебного Prod-стенда SQL Trainer выделяются следующие инфраструктурные элементы.

1. **Рабочая станция сотрудника**

* Ноутбук или рабочий ПК сотрудника (обучающийся, методист, администратор).
* Доступ к Системе осуществляется через веб-браузер по HTTPS:

    * либо из внутренней корпоративной сети;
    * либо через подключение по VPN к корпоративному контуру.

2. **VPN / корпоративный доступ**

* Существующая в компании инфраструктура VPN/корпоративного доступа.
* Обеспечивает защищённый канал между рабочей станцией и внутренней сетью, где размещён SQL Trainer.

3. **Периметровый узел приложения (Nginx + Static UI)**

* Виртуальная машина или физический сервер во внутренней сети компании.
* На узле размещены:

    * веб-сервер **Nginx**, выполняющий роль reverse proxy и точки входа HTTPS (порт 443);
    * статический бандл фронтенда (React SPA), размещённый на файловой системе и отдаваемый Nginx как статика.
* Основные функции узла:

    * приём входящих HTTPS-запросов от браузеров сотрудников;
    * терминация TLS;
    * отдача статических файлов UI;
    * проксирование запросов к backend-сервисам в кластере Kubernetes по внутренним HTTP(S) эндпоинтам;
    * взаимодействие с Keycloak для проверки и получения параметров токена (JWKS, introspection) в рамках модели безопасности.

4. **Кластер приложений (App Tier, Kubernetes Cluster)**

* Внутренний кластер Kubernetes, развёрнутый на серверах/виртуальных машинах провайдера Hetzner или в эквивалентном корпоративном сегменте.
* В отдельном namespace размещены pod’ы backend-сервисов SQL Trainer:

    * **Users/Auth Service**;
    * **Courses/Tasks Service**;
    * **Execution Service**;
    * **Progress/Reporting Service**.
* Внутри кластера используются стандартные объекты Kubernetes (Deployments, Services, ConfigMaps, Secrets).
* Внешний доступ к сервисам кластера осуществляется только через Nginx; прямой доступ из пользовательской сети к кластера Kubernetes не предоставляется.

5. **Сервер `App DB` (PostgreSQL)**

* Отдельная виртуальная машина или управляемый инстанс PostgreSQL во внутренней сети.
* Предназначен для хранения сервисных данных Системы:

    * курсы, модули, задачи, настройки;
    * пользователи и их данные в контексте тренажёра;
    * история попыток, агрегированная отчётность.
* Доступ к `App DB` разрешён только backend-сервисам в кластере Kubernetes по порту 5432 (PostgreSQL).
* Доступ из пользовательской сети и с других прикладных серверов, не входящих в контур SQL Trainer, запрещён политиками сети и firewall.

6. **Сервер `Training DB` (PostgreSQL)**

* Отдельная виртуальная машина или управляемый инстанс PostgreSQL, логически и физически отделённый от `App DB`.
* Хранит учебные схемы и данные, над которыми выполняются SQL-запросы обучающихся.
* Доступ к `Training DB` имеют только backend-сервисы в кластере Kubernetes, прежде всего **Execution Service**, по порту 5432.
* Прямой доступ из пользовательской сети и других приложений компании не предусмотрен и запрещён на уровне сетевой конфигурации.

7. **Зона идентификации (SSO / Keycloak и Active Directory)**

* **Keycloak**:

    * размещён на выделённых серверах или в отдельной инфраструктурной зоне;
    * обеспечивает аутентификацию пользователей по протоколам OIDC/OAuth2;
    * интегрирован с Active Directory и взаимодействует с ним по LDAP/LDAPS.
* **Active Directory**:

    * корпоративный каталог учётных записей, групп и атрибутов пользователей;
    * используется Keycloak для проверки подлинности и получения атрибутов.
* SQL Trainer взаимодействует с этой зоной следующим образом:

    * браузер пользователей перенаправляется на Keycloak при аутентификации;
    * Nginx (как периметровый компонент) использует Keycloak для проверки валидности токенов доступа (получение JWKS, проверка подписи и пр.).

8. **Зона управления и наблюдаемости (Management Subnet)**

* Включает инфраструктурные компоненты, используемые несколькими системами компании, в том числе SQL Trainer:

    * **CI/CD-пайплайн**: выполняет сборку и деплой backend-сервисов в кластер Kubernetes, а также миграции схемы баз данных через согласованные механизмы;
    * **Мониторинг и логирование** (например, Prometheus, Grafana, централизованный сбор логов): собирают метрики и журналы работы backend-сервисов и баз данных.

---

#### 4.3.3. Сетевые взаимодействия и порты

На уровне Deployment View фиксируются следующие ключевые сетевые взаимодействия:

* Браузер пользователя подключается к серверу с Nginx по **HTTPS 443** (через корпоративную сеть или VPN).
* Nginx:

    * отдаёт статический фронтенд (React SPA);
    * проксирует REST API-запросы к backend-сервисам в кластере Kubernetes по внутренним HTTP(S)-эндпоинтам.
* Backend-сервисы в Kubernetes подключаются к:

    * `App DB` по **TCP 5432** (PostgreSQL, JDBC);
    * `Training DB` по **TCP 5432** (PostgreSQL, JDBC, в основном Execution Service).
* Браузер пользователей взаимодействует с Keycloak по **HTTPS** при аутентификации.
* Nginx взаимодействует с Keycloak по **HTTPS** для проверки токенов (получение JWKS и других необходимых данных).
* Keycloak взаимодействует с Active Directory по **LDAP/LDAPS** для проверки учётных данных и получения атрибутов пользователей.
* Системы мониторинга опрашивают backend-сервисы и базы данных по согласованным HTTP/HTTPS-эндпоинтам метрик либо через экспортёры для PostgreSQL.

---

#### 4.3.4. Особенности развёртывания Dev/Test/Prod

* Архитектурно Dev и Test-среды повторяют Prod-среду по структуре (периметр, кластер Kubernetes, App DB, Training DB, SSO), но:

    * могут использовать облегчённую конфигурацию кластера и баз данных;
    * могут не иметь полного набора учебных данных и курсов.
* SQL Trainer не предназначен для использования в средах с прямым доступом из Интернета и должен оставаться внутри корпоративного контура во всех средах (Dev/Test/Prod).

Deployment View, описанный выше, является базой для Security View, где дополнительно выделяются зоны безопасности, сетевые границы и ограничения доступа между ними.
