## 4. Архитектурные представления (Views)

### 4.1. System Context View

#### 4.1.1. Назначение представления

System Context View описывает Систему «SQL Trainer» как единый чёрный ящик во внутреннем ландшафте компании. Цель представления — показать,
кто взаимодействует с Системой, через какие технические средства и какие внешние системы вовлечены, без детализации внутренней структуры и технологий реализации.

Данное представление используется для согласования границ Системы, зон ответственности и основных сценариев взаимодействия с ключевыми стейкхолдерами (бизнес, ИБ, архитекторы, эксплуатация).

---

#### 4.1.2. Основные элементы контекста

В рамках System Context View рассматриваются следующие элементы:

* **SQL Trainer**

    * внутренняя учебная веб-система для решения задач по SQL и анализа прогресса обучения;
    * представляется как единый логический компонент, скрывающий внутреннюю микросервисную структуру.

* **Браузер пользователя**

    * основной клиентский интерфейс для доступа к Системе;
    * запускается на рабочей станции сотрудника в корпоративной сети или при подключении по VPN;
    * взаимодействует с SQL Trainer по протоколу HTTPS.

* **Корпоративный SSO/Keycloak**

    * сервер аутентификации и авторизации;
    * отвечает за вход пользователей в Систему, выдачу токенов и передачу информации о ролях;
    * интегрирован с Active Directory.

* **Active Directory (AD)**

    * корпоративный каталог учетных записей пользователей;
    * хранит учётные записи, пароли и групповую принадлежность;
    * используется Keycloak для проверки подлинности пользователей и получения дополнительных атрибутов.

---

#### 4.1.3. Акторы

В контекст Системы входят следующие категории пользователей:

* **Обучающийся (Сотрудник)**

    * входит в Систему через SSO;
    * просматривает доступные курсы и задачи;
    * решает задачи, отправляя SQL-запросы на проверку;
    * просматривает результаты и свой прогресс.

* **Методист / Руководитель**

    * входит в Систему через SSO;
    * создаёт и редактирует курсы, модули и задачи;
    * настраивает учебные данные и эталонные решения;
    * анализирует отчёты по прогрессу обучающихся и типичным ошибкам.

* **Администратор**

    * входит в Систему через SSO;
    * выполняет массовый импорт/экспорт задач и учебных данных;
    * управляет техническими настройками Системы в пределах предоставленного функционала.

Все указанные акторы взаимодействуют с Системой только через веб-интерфейс в браузере, прямой доступ к базам данных и микросервисам Системы не предусмотрен.

---

#### 4.1.4. Взаимодействия на уровне контекста

На уровне контекста выделяются следующие основные взаимодействия:

1. **Вход в Систему и аутентификация**

    * Пользователь открывает SQL Trainer в браузере из корпоративной сети или по VPN.
    * SQL Trainer перенаправляет запрос на SSO/Keycloak для аутентификации.
    * Keycloak, при необходимости, взаимодействует с Active Directory для проверки учетных данных.
    * После успешной аутентификации пользователю предоставляется доступ к функционалу Системы в соответствии с его ролями.

2. **Работа обучающегося**

    * Обучающийся через браузер запрашивает список доступных курсов и задач.
    * SQL Trainer возвращает необходимые данные и отображает их в интерфейсе.
    * Обучающийся открывает задачу, вводит SQL-запрос и отправляет его на проверку.
    * SQL Trainer выполняет проверку и возвращает результат и статус попытки.

3. **Работа методиста и администратора**

    * Методист и администратор через браузер обращаются к SQL Trainer с учётом своих ролей.
    * Методист управляет учебным контентом и просматривает отчётность.
    * Администратор выполняет технические операции в рамках предоставленных интерфейсов.

---

#### 4.1.5. Границы Системы

На уровне System Context View фиксируются следующие границы:

* SQL Trainer рассматривается как единая логическая система, включающая пользовательский интерфейс, серверную часть и базы данных.
* Корпоративный SSO/Keycloak и Active Directory относятся к внешним системам, поддерживаемым другими командами и используемым SQL Trainer для аутентификации и получения данных о пользователях.
* Пользовательские рабочие станции, браузеры и VPN-инфраструктура входят в корпоративный контур, но не являются частью Системы SQL Trainer.

Данное представление служит исходной точкой для дальнейшего уточнения архитектуры на уровне Container View, Deployment View и Security View.
