### 3.2. Основные подсистемы

В составе Системы «SQL Trainer» выделяются следующие основные подсистемы и компоненты. Дальнейшие архитектурные представления (Context, Container, Deployment, Security View) опираются именно на этот набор подсистем.

1. **Пользовательский интерфейс (Frontend, React SPA)**

  * Одностраничное веб-приложение на базе React, работающее в браузере пользователя.
  * Обеспечивает:

    * аутентификацию через SSO (совместно с backend и Keycloak);
    * отображение списка курсов, модулей и задач;
    * интерфейс просмотра условий задач, учебных данных и подсказок;
    * редактор SQL-запросов (операторы `SELECT`) и отправку решений на проверку;
    * отображение результатов проверки, прогресса и базовых отчётов для пользователей с соответствующими правами.
  * Развёртывается в кластере Kubernetes и обслуживается через Nginx.

2. **Серверная часть (Backend, микросервисы на Java/Spring)**

  * Набор серверных сервисов, реализованных на Java с использованием Spring и развернутых в кластере Kubernetes.
  * Логически выделяются следующие доменные сервисы (набор может уточняться по результатам проектирования Component View):

    * **Users/Auth** – работа с данными пользователей в рамках Системы, получение и проверка ролей, интеграция с SSO на прикладном уровне;
    * **Courses/Tasks** – управление курсами, модулями и задачами, доступ к их описанию и настройкам;
    * **Execution** – выполнение учебных SQL-запросов над `Training DB`, сравнение с эталоном и формирование вердикта;
    * **Progress/Reporting** – хранение и агрегирование истории попыток, расчёт прогресса, предоставление данных для отчётности.
  * Сервисы взаимодействуют между собой по внутренним API и обращаются к базам данных `App DB` и `Training DB`.

3. **Сервисная база данных приложения (App DB, PostgreSQL)**

  * Хранит сервисные данные Системы:

    * пользователи и их роли в контексте тренажёра;
    * курсы, модули, задачи, настройки;
    * история попыток решения задач (включая текст SQL-запросов, результаты, длительность выполнения);
    * агрегированные данные для базовой отчётности и прогресса.
  * Используется backend-сервисами для всех операций по управлению контентом и прогрессом обучения.

4. **Учебная база данных (Training DB, PostgreSQL)**

  * Содержит учебные схемы и наборы данных, над которыми выполняются учебные SQL-запросы обучающихся.
  * Не содержит реальных боевых данных и не используется как источник производственной аналитики.
  * Доступна только сервисам backend (в первую очередь подсистеме Execution) по защищённому соединению.
  * Структура и наполнение учебных схем управляются методистами и администраторами через соответствующие механизмы Системы и миграций.

5. **Подсистема аутентификации и авторизации (SSO/Keycloak, Active Directory)**

  * **Keycloak/SSO**:

    * обеспечивает аутентификацию пользователей по корпоративным учётным данным;
    * выдаёт токены доступа и сведения о ролях пользователей;
    * интегрирован с Active Directory как источником учетных записей.
  * **Active Directory**:

    * корпоративный каталог пользователей;
    * управление учётными записями и паролями находится на стороне корпоративных служб.
  * SQL Trainer использует SSO для входа пользователей и проверки прав доступа, локальные пароли не хранятся.

6. **Периметр и маршрутизация (Nginx / API Gateway-логика)**

  * Внутренний веб-сервер **Nginx**:

    * является точкой входа HTTP/HTTPS в Систему;
    * обслуживает статические ресурсы фронтенда;
    * маршрутизирует запросы к микросервисам backend в кластере Kubernetes;
    * настраивается как точка терминации TLS и может выполнять часть логики API-шлюза (проверка токенов, базовый контроль доступа) в рамках согласованной модели безопасности.

7. **Подсистемы эксплуатации и наблюдаемости (CI/CD, мониторинг, логирование)**

  * **CI/CD-пайплайн**:

    * автоматизирует сборку и доставку фронтенда и микросервисов backend в Kubernetes;
    * выполняет тесты и миграции баз данных при деплое на среды Dev, Test и Prod.
  * **Мониторинг и логирование**:

    * сбор метрик по времени проверки задач, нагрузке на `Training DB`, ошибкам аутентификации и другим ключевым показателям;
    * сбор логов попыток выполнения задач и технических логов сервисов для анализа инцидентов и производительности.

Перечисленные подсистемы образуют целостное решение: пользовательский интерфейс в браузере, микросервисный backend в Kubernetes, отдельные базы данных для сервисных и учебных данных, интеграция с корпоративным SSO, а также инфраструктуру для безопасной эксплуатации и наблюдаемости Системы.
