## 1. Введение

### 1.1. Цель документа и аудитория

Настоящий документ описывает целевое архитектурное решение для внутренней системы «SQL Trainer» (далее — Система). Документ фиксирует структуру Системы, ключевые архитектурные решения, риски и допущения, а также подход к эксплуатации и развитию.

Документ предназначен для следующих категорий читателей:

* **Архитекторы и разработчики** — для понимания целевой архитектуры, ограничений и принятых решений.
* **Инженеры по тестированию** — для понимания границ Системы, ключевых сценариев и нефункциональных требований.
* **Инженеры эксплуатации и DevOps** — для понимания ландшафта развёртывания, сред, интеграций и требований к мониторингу.
* **Руководители проектов и менеджеры** — для оценки соответствия архитектуры бизнес-целям и ограничениям по срокам и ресурсам.
* **Представители службы информационной безопасности** — для анализа используемых механизмов аутентификации, авторизации и защиты данных.

Документ является исходной точкой для архитектурных ревью, планирования работ по реализации и дальнейшего развития Системы.

---

### 1.2. Цели системы SQL Trainer / бизнес-контекст

Система «SQL Trainer» предназначена для внутреннего использования сотрудниками компании в целях обучения и отработки навыков работы с SQL (операторы `SELECT`).

Основные бизнес-цели:

* **Ускорение онбординга** аналитиков, разработчиков и других сотрудников, которым требуется рабочее владение SQL.
* **Выравнивание минимального уровня компетенций** по SQL внутри компании за счёт единого набора курсов и задач.
* **Получение прозрачной статистики по прогрессу сотрудников**: какие курсы пройдены, по каким темам возникают сложности, где концентрируются типичные ошибки.

Система является **внутренним учебным стендом**, не обрабатывает боевые клиентские данные и не предназначена для внешних пользователей.

---

### 1.3. Ключевые метрики успеха MVP

Для минимально жизнеспособной версии (MVP) устанавливаются следующие целевые показатели:

* **Нагрузка/использование:**

    * не менее **20 решённых задач в день** на одного стажёра/обучающегося в активный период обучения.

* **Производительность:**

    * среднее время проверки одной задачи (выполнение запроса + сравнение результата) — **не более 1 секунды** для типовых учебных задач при штатной нагрузке.

Данные метрики используются для оценки успешности внедрения MVP и могут уточняться по мере эксплуатации Системы.

---

### 1.4. Область применения и доступ

Система «SQL Trainer» относится к классу внутренних корпоративных учебных веб-приложений и эксплуатируется только во внутренней инфраструктуре компании.

Основные ограничения:

* Доступ к Системе возможен **только из корпоративной сети** либо через защищённое **подключение по VPN**.
* Аутентификация и базовые роли пользователей выполняются через корпоративный **SSO/Keycloak**, интегрированный с **Active Directory**.
* Публикация Системы во внешние сети (Интернет) **не предусматривается**.
* Система рассчитана на использование сотрудниками компании (стажёры, аналитики, разработчики, методисты, администраторы) и не предназначена для внешних клиентов.

Область действия документа ограничена архитектурой учебного стенда SQL Trainer в рамках соглашений и требований компании к внутренним системам.

### 1.5. Термины и сокращения (Glossary)

В рамках настоящего документа используются следующие термины и сокращения:

* **Система, SQL Trainer** — корпоративное веб-приложение для обучения сотрудников работе с SQL на основе решения задач.
* **Обучающийся (Сотрудник)** — пользователь, проходящий курсы и решающий задачи в Системе.
* **Методист** — пользователь, создающий и редактирующий курсы, задачи и учебные наборы данных, анализирующий результаты обучения.
* **Администратор** — пользователь, выполняющий технические операции с задачами и учебными данными, а также базовую конфигурацию Системы.
* **Курс (Course)** — логическое объединение учебных модулей и задач по SQL.
* **Задача (Task)** — отдельное упражнение по SQL с формулировкой условия, учебными данными и эталонным решением.
* **Попытка (Attempt)** — один запуск решения задачи обучающимся (SQL-запрос + результат проверки).
* **App DB** — сервисная база данных Системы, содержащая курсы, задачи, пользователей, историю попыток, отчёты и настройки.
* **Training DB** — учебная база данных, содержащая учебные схемы и наборы данных, над которыми выполняются учебные SQL-запросы.
* **Учебные данные** — синтетические или обобщённые данные, используемые в `Training DB` только для учебных задач и не содержащие боевой клиентской информации.
* **SSO (Single Sign-On)** — механизм единого входа в корпоративные системы.
* **Keycloak** — используемый в компании сервер аутентификации/авторизации, реализующий SSO и протоколы OIDC/OAuth2.
* **Active Directory (AD)** — корпоративный каталог учетных записей пользователей.
* **Execution (подсистема выполнения запросов)** — часть backend-логики, отвечающая за выполнение SQL-запросов обучающихся в `Training DB`, сравнение результата с эталоном и формирование вердикта.
* **MVP (Minimum Viable Product)** — минимально жизнеспособная версия Системы, реализующая основной учебный функционал при ограниченном объёме задач и отчётности.

При возникновении неоднозначностей терминология настоящего раздела имеет приоритет над иными внутренними документами, если явно не указано иное.

### 1.6. Внешние ссылки и исходные документы

Настоящий архитектурный документ опирается на следующие исходные материалы и регламенты:

1. **Техническое задание на систему «SQL Trainer»**

    * описание целей проекта, ролей пользователей, функциональных и нефункциональных требований, ограничений по срокам и стеку технологий.

2. **Учебные материалы по архитектуре ПО (лекция по архитектурной документации и AVD)**

    * методические рекомендации по структуре архитектурного документа, составу архитектурных представлений, фиксации ключевых решений, рисков и допущений.

3. **Корпоративные политики и регламенты информационной безопасности**

    * политика ИБ в части разработки и эксплуатации внутренних систем;
    * требования к использованию учебных данных;
    * требования к аутентификации и авторизации (SSO/Keycloak, AD, VPN).

4. **Внутренние стандарты разработки и эксплуатации**

    * стандарты по использованию Java, Spring, React и PostgreSQL;
    * стандарты по CI/CD, мониторингу, логированию и резервному копированию для внутренних приложений.

При противоречиях между настоящим документом и внешними нормативными документами приоритет имеют корпоративные политики и регламенты компании; архитектурный документ подлежит актуализации.
