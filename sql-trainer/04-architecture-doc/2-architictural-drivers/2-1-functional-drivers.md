## 2. Архитектурные драйверы

### 2.1. Функциональные драйверы

Функциональные драйверы описывают ключевые пользовательские сценарии и возможности, ради которых создаётся Система. Они определяют минимальный набор функционала, который должен быть реализован в рамках MVP.

Основные функциональные драйверы для SQL Trainer:

1. **Прохождение курсов и решение задач по SQL обучающимися**

    * Обучающийся должен иметь возможность:

        * войти в Систему через корпоративный SSO;
        * просмотреть список доступных курсов и модулей;
        * открыть курс, увидеть структуру (модули, задачи);
        * выбрать задачу, прочитать условие и при необходимости примеры данных;
        * ввести SQL-запрос (операторы `SELECT`) в веб-редакторе и отправить его на проверку;
        * получить результат проверки (вердикт, результат запроса, комментарий).

2. **Проверка решений на учебных данных**

    * Backend Системы должен:

        * выполнить переданный обучающимся SQL-запрос над соответствующей учебной схемой в `Training DB`;
        * сравнить результат с эталонным результатом/запросом;
        * сформировать вердикт (**верно / частично / неверно**) и вернуть его в UI.

3. **Ведение истории попыток и прогресса обучающихся**

    * Система должна сохранять:

        * все попытки решения задач (пользователь, задача, время, текст SQL-запроса, результат, длительность выполнения);
        * агрегированную информацию о прогрессе по курсам (пройдено / не пройдено, процент выполнения);
    * Данные истории используются для:

        * отображения прогресса самому обучающемуся;
        * формирования отчётов для методистов и руководителей.

4. **Создание и сопровождение учебного контента методистами**

    * Методист должен иметь возможность:

        * создавать и редактировать курсы, модули и задачи;
        * определять учебные наборы данных и учебные схемы в `Training DB`;
        * задавать эталонные решения или эталонные результаты для задач;
        * управлять подсказками и возможностью просмотра правильного решения (по настройкам курса).

5. **Базовая отчётность для методистов и руководителей**

    * Система должна предоставлять:

        * отчёты по прохождению курсов (по сотрудникам, группам, подразделениям);
        * базовую статистику по задачам (частота ошибок, среднее количество попыток, среднее время решения);
        * возможность идентифицировать “проблемные” темы и задачи.

6. **Администрирование учебных данных и задач**

    * Администратор должен иметь возможность:

        * выполнять массовый импорт/экспорт задач и учебных данных (например, из файлов);
        * управлять техническими настройками Системы, влияющими на доступность и использование учебного контента (включение/выключение курсов, ограничение функционала подсказок и т.п.).
