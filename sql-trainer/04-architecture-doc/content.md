## 5. Ключевые архитектурные решения (Key Decisions)

5.1. **KD1: Управление нагрузкой на Training DB (таймаут 2 сек, пул 50, очередь)** — **[ГОТОВО]**

* Оформлено в формате Context / Decision / Consequences.

5.2. **KD2: Авторизация через SSO и проверка JWT только на входе (MVP only)** — **[ГОТОВО]**

* Валидация на шлюзе, сервисы доверяют claims, пометка “только для учебного стенда”.

5.3. **Разделение App DB и Training DB (разные сервера)** — **[ЧЕРНОВИК]**

* Смысл проговорён многократно, нужно оформить как отдельное KD.

5.4. **Выбор стека и архитектурного стиля** — **[ЧЕРНОВИК]**

* React SPA + Java Spring монолит-платформа в MVP с перспективой микросервисов.

5.5. **Только внутренняя сеть/VPN, без публичного доступа** — **[ЧЕРНОВИК]**

* Это сейчас в Security/Deployment, стоит оформить как отдельное KD.

(Тут у тебя уже есть два полноценных KD и пару легко оформить из обсуждений.)

## 8. План развития архитектуры (Roadmap / Evolution)

8.1. **Выделение доменов в микросервисы** — **[ЧЕРНОВИК]**

* tasks/users/progress/execution как кандидаты.

8.2. **Реплика Training DB для аналитики/BI** — **[ЧЕРНОВИК]**

* read-only реплика, eventual consistency, не ломает основную модель безопасности.

8.3. **Ужесточение безопасности** — **[ЧЕРНОВИК]**

* переход к Authorization Code + PKCE / BFF;
* валидация JWT в каждом сервисе;
* возможное использование introspection в чувствительных сценариях.
