### 5.5. KD5: Только внутренняя сеть/VPN, без публичного доступа

**Context**

* SQL Trainer — **внутренний учебный стенд**, предназначенный для сотрудников компании (стажёры, аналитики, методисты, администраторы).
* В системе используются **учебные данные**, но при этом логируются действия сотрудников, хранятся их попытки, прогресс, отчёты и т.п.
* В компании уже существует стандартная схема доступа:

    * корпоративная сеть;
    * удалённый доступ через VPN;
    * централизованный SSO (Keycloak/AD).
* Система не должна быть доступна внешним пользователям (кандидатам, партнёрам и т.д.) и не является публичным сервисом.
* Усложнение периметра (WAF, публикация в интернет, дополнительный DMZ) **не требуется** для учебного MVP и добавило бы избыточную инфраструктурную сложность.

---

**Decision**

1. **SQL Trainer доступен только из внутренней сети или через VPN**

    * Веб-интерфейс тренажёра (Nginx + SPA) публикуется **только во внутреннем корпоративном сегменте**.
    * Доступ возможен:

        * с рабочих станций в корпоративной сети;
        * либо при подключении по корпоративному VPN.

2. **Отсутствие публичного доступа из Интернета**

    * Публичная публикация SQL Trainer во внешний периметр (через интернет-шлюзы, внешние домены и т.п.) **не выполняется**.
    * Любой входящий HTTP(S)-трафик к SQL Trainer снаружи компании блокируется на уровне сети и периметровых средств.

3. **Единственный пользовательский протокол – HTTPS к Nginx**

    * Пользователи взаимодействуют с системой только через браузер по HTTPS (порт 443/tcp) к Nginx.
    * Любые другие варианты доступа (прямое подключение к базам данных, backend-сервисам, SSH-доступ к серверам и т.п.) относятся к административному контуру и регулируются отдельными политиками ИБ и эксплуатации.

---

**Consequences**

Положительные последствия:

* **Существенное упрощение модели угроз**:

    * нет необходимости защищать систему от произвольного внешнего трафика из Интернета;
    * основной фокус переносится на внутреннюю безопасность (роли, разграничение прав, защита БД, SSO).
* **Снижение требований к периметру** для учебного стенда:

    * можно обойтись внутренним Nginx без сложного внешнего WAF и отдельного DMZ для публичного доступа;
    * меньше инфраструктуры для поддержки и мониторинга.
* Легче объяснить и согласовать модель с ИБ:

    * “только внутренний ресурс под VPN” хорошо ложится в типовые корпоративные политики;
    * меньше вопросов про хранение и защиту данных на внешнем периметре.

Негативные и ограничивающие последствия:

* **Невозможность использования тренажёра извне** без VPN:

    * сотрудники, работающие вне корпоративной сети, обязаны использовать VPN для доступа;
    * невозможен доступ кандидатов, внешних стажёров, партнёров, если не выдан VPN/временной доступ.
* В случае решения развивать SQL Trainer как внешний продукт (например, для учебного портала) потребуется:

    * пересматривать модель размещения;
    * добавлять DMZ, WAF, дополнительные меры защиты;
    * обновлять Security View и Deployment View.

Данное решение фиксирует, что SQL Trainer в рамках текущего проекта является **исключительно внутренней системой под VPN**, без публичного доступа из Интернета. Это осознанный компромисс в пользу простоты и безопасности для учебного стенда.
