## Состав папок

### 01-context-sep — старт архитектуры (сентябрь)
`С1.puml` — контекстная диаграмма; `С2.puml`, `С2-2.puml` — контейнеры;
`identity-service.md` — аутентификация через Active Directory (bind,
группы → роли Стажёр/Тимлид/Администратор), JWT с userId/roles/exp,
проверка Bearer на Gateway, отзыв при logout;
`schema-service.md` — снимок структуры учебных БД (схемы/таблицы/PK/FK/
индексы/вьюхи), нормализация типов, кеш в собственной БД, шедулер
обновления; источник — PostgreSQL / MySQL / SQL Server, доступ
внутрикорпоративный (VPN).

### 02-containers-oct — итерации контейнеров (октябрь)
`С2-3/4/5` — эволюция контейнерной диаграммы; `С2-sql-academy.puml` —
полный контур SQL Academy (ученик/ментор; Edge: Ingress/WAF + BFF;
домены Auth/OAuth/Tasks/Schema/Progress/Certificates/Billing/Admin/
Notifications; Execution Subsystem — исполнение SQL); `С2-sql-academy-2`
— вырез/фокус; `er.puml` + `er.mermaid` — модель данных в двух нотациях.

### 03-development-oct — развитие и развёртывание
`step-1.puml`, `step-2.puml` — пошаговые итерации архитектуры;
`depl-1/2/3.puml` — диаграммы развёртывания с легендой цветовых зон
DEV (#E6F3FF) / STAGE (#FFF2CC) / PROD (#FFE6E6).

### 04-architecture-doc — полный архитектурный документ (ноябрь–декабрь)
Профессиональная структура (SEI-дисциплина: драйверы → виды → решения →
риски → DevOps → эволюция по атрибутам качества):
- `content.md` — план-трекер написания со статусами [ГОТОВО]/[ЧЕРНОВИК]/
  [НУЖНО НАПИСАТЬ] — управление качеством собственного документа
- `1-introduction` — метрики успеха MVP: ≥20 задач/день на стажёра,
  проверка запроса ≤1 сек; VPN-only, только корпоративные сотрудники
- `2-architictural-drivers` — функциональные, нефункциональные, ограничения, риски
- `3-solution-overview` — e2e-сценарий, подсистемы, подключение к среде компании
- `4-architectural-views` + `applications/9-1-schemes` — контекст, контейнеры,
  развёртывание, безопасность
- `5-key-decisions` — 5 ADR: управление нагрузкой, авторизация, базы данных,
  стиль архитектуры, VPN
- `6-risks-*` — риски, допущения, стратегии митигации
- `7-devops` — окружения, мониторинг, логирование, CI/CD, миграции БД,
  backup/restore
- `8-evolution` — эволюция по 4 атрибутам качества: доступность (20 КБ),
  деплойность (33 КБ), интегрируемость (28 КБ), модифицируемость (30 КБ)
  + диаграммы фасадов и зависимостей before/after + sequence

### 05-mvp-code-nov — работающий MVP (ноябрь, код Василия)
`execution-api`: Application / ExecutionController / ExecutionService (192
строки: ThreadPoolExecutor 4×16 с AbortPolicy → QueueFullException; таймаут
1000 мс через future.cancel; auto-limit 200; allow-only-select — защита
песочницы) + Dockerfile + application.properties.
`tasks-service`: TaskController / TaskDto / TaskRepository + Dockerfile.
`k8s`: 7 манифестов — namespace, secrets, два PostgreSQL (app- и
training-БД), execution + config + api, tasks-service.

(04): «проверка запроса ≤1 сек» → таймаут пула; устойчивость к перегрузке →
очередь с отказом. Порядок работы: диаграммы (октябрь) → работающий
код в K8s (02–11.11) → архитектурный документ (22.11+) — гипотезы
проверялись кодом до фиксации решений.
