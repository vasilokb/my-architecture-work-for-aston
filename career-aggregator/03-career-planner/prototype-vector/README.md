# Прототип векторной БД (pgvector) для Генриха

Отвечает на вопрос «как определяется процент похожести» на реальных данных.
Запущен и проверен: 95 скиллов, 20 вакансий трёх технологий, демо-пользователь demo.
Все ответы в battle-examples.sql — реальные, снятые с работающей БД.

## Запуск

1. `docker-compose up -d`
2. `pip install sentence-transformers psycopg2-binary`
3. `python load_skills.py` — справочник скиллов с векторами
4. `python seed_demo.py` — пользователь demo + 20 вакансий
5. DBeaver: localhost:5433, база prototype, career/career
6. Открыть `battle-examples.sql` (боевые сценарии) или `query.sql` (быстрая проверка)

## Файлы

- `battle-examples.sql` — 6 сценариев запрос/ответ: как выглядит вектор, топ похожих скиллов, матчинг пользователя с вакансиями, контроль по всем технологиям, порог релевантности, сравнение мер расстояния, итоговый JSON API
- `query.sql` — минимальный запрос для быстрой проверки
- `seed_demo.py` — наполнение боевых таблиц

## Как считается процент

- Вектор 384 измерения от all-MiniLM-L6-v2 (та же модель, что в основном проекте), нормализованный
- `<=>` = косинусное расстояние; похожесть = 1 − расстояние; процент = ×100
- Матчинг вакансии: каждый требуемый скилл вакансии матчится с лучшим скиллом пользователя (MAX), среднее по скиллам = процент покрытия
- Предфильтр по технологии работает ДО векторного поиска
- ВАЖНО: во всех ROUND каст ::numeric — в Postgres нет ROUND(double precision, int)

## Реальные результаты (снятые с прототипа)

- Матчинг demo по своей технологии: 48.4–67.2%, ранжирование осмысленное (вакансии аналитика требуют 6-8 скиллов, из 4 скиллов пользователя точных совпадений 2-4)
- Без предфильтра: Системный аналитик 58.7%, Data Engineer 42.0%, Java 38.2% — вектор различает области, но порог и предфильтр нужны оба
- Косинус и внутреннее произведение на нормализованных векторах дают одинаковые проценты (проверено)

## Ограничение, выявленное на прототипе

На коротких голых токенах модель работает ближе к сравнению строк:
SQL → MySQL 68.7 работает, но BPMN → UML всего 22.9, в топе шум (C++ 32.6).
Для прод: кодировать скиллы с контекстом (расшифровка из справочника Цербера),
либо модель крупнее, либо опираться на предфильтр + точные совпадения,
а вектор — как ранжирование внутри.
