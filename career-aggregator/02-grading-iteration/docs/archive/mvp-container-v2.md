# Контейнерная диаграмма - MVP поиска вакансий для уходящих сотрудников (v2)

## Описание MVP

Правильная версия системы с хранением данных и процессом формирования профиля позиции. Минимум компонентов, но с полноценным хранением.

## Ключевые отличия от v1

1. **Добавлено хранение данных**: PostgreSQL для持久化 данных
2. **Добавлен Profile Service**: Управление профилями позиций
3. **Добавлен Redis**: Кэширование вместо in-memory cache
4. **Процесс формирования профиля позиции**: Карьерный консультант создает профиль, уходящий сотрудник использует его для поиска

## Контейнеры системы

### 1. Web Application (Streamlit)
- **Технология**: Streamlit
- **Назначение**: Пользовательский интерфейс
- **Функции**:
  - **Для карьерного консультанта**: Форма создания/редактирования профиля позиции
  - **Для уходящего сотрудника**: Выбор профиля позиции, просмотр вакансий
  - **Панель администратора**: Управление доступом, мониторинг активности
- **Преимущества**:
  - Простая реализация (Python)
  - Быстрый старт
  - Встроенные компоненты UI

### 2. API Gateway (FastAPI)
- **Технология**: FastAPI
- **Назначение**: Прием запросов, аутентификация, маршрутизация, rate limiting
- **Функции**:
  - Аутентификация пользователей (JWT)
  - Rate limiting (2 запроса в день на пользователя)
  - Маршрутизация в Search Service и Profile Service
  - Управление сессиями
- **Преимущества**:
  - Простая реализация
  - Автоматическая документация API
  - Высокая производительность

### 3. Search Service (Python/FastAPI)
- **Технология**: Python/FastAPI
- **Назначение**: Основной сервис поиска вакансий
- **Функции**:
  - **Формирование запроса к HH.ru**: На основе профиля позиции
  - **LLM-парсинг профиля**: Преобразование профиля позиции в структурированные параметры для HH.ru через DeepSeek API
  - **Поиск вакансий**: Запрос к HH.ru API для получения вакансий
  - **Генерация эмбеддингов**: Создание векторных представлений через sentence-transformers
  - **Семантическое ранжирование**: Сравнение векторов профиля и вакансий (косинусное сходство)
  - **Кэширование**: Сохранение результатов в Redis
- **Преимущества**:
  - Все в одном сервисе (простота)
  - Минимум межсервисного взаимодействия
  - Легко отлаживать

### 4. Profile Service (Python/FastAPI)
- **Технология**: Python/FastAPI
- **Назначение**: Управление профилями позиций
- **Функции**:
  - **Создание профиля позиции**: Специальность, навыки, опыт, зарплата, город
  - **Редактирование профиля**: Изменение параметров
  - **Хранение профилей**: Сохранение в PostgreSQL
  - **Получение профилей**: Для использования в поиске
- **Структура профиля позиции**:
  ```json
  {
    "id": "uuid",
    "name": "Java-разработчик",
    "specialty": "Java",
    "skills": ["Spring Boot", "Hibernate", "PostgreSQL"],
    "experience_years": 3,
    "salary_from": 150000,
    "salary_to": 250000,
    "city": "Москва",
    "employment_type": "full",
    "created_by": "consultant_id",
    "created_at": "timestamp"
  }
  ```

### 5. PostgreSQL
- **Технология**: PostgreSQL
- **Назначение**: Хранение данных
- **Таблицы**:
  - `users`: Пользователи (карьерные консультанты, уходящие сотрудники)
  - `position_profiles`: Профили позиций
  - `search_history`: История запросов
  - `search_results`: Результаты поиска (вакансии с процентным соответствием)
- **Преимущества**:
  - Надежное хранение
  - Поддержка сложных запросов
  - Хорошая производительность

### 6. Redis
- **Технология**: Redis
- **Назначение**: Кэширование
- **Функции**:
  - Кэширование ответов от DeepSeek API
  - Кэширование эмбеддингов
  - Кэширование результатов поиска
  - Хранение сессий пользователей
- **Преимущества**:
  - Быстрый доступ
  -持久化 (при необходимости)
  - Простая реализация

### 7. Embedding Engine (Sentence-Transformers)
- **Технология**: Sentence-Transformers (all-MiniLM-L6-v2)
- **Назначение**: Генерация эмбеддингов для ранжирования
- **Функции**:
  - Векторизация профиля позиции
  - Векторизация описаний вакансий
  - Косинусное сходство для сравнения
- **Требования к ресурсам**:
  - Память: 200-500 МБ
  - Диск: 80 МБ для модели

## Внешние системы

### 1. DeepSeek API
- **Назначение**: LLM для преобразования профиля позиции в структурированные параметры для HH.ru
- **Функции**:
  - Парсинг профиля позиции
  - Извлечение ключевых слов для поиска
  - Формирование запроса к HH.ru API
  - Возврат структурированного JSON

### 2. HH.ru API
- **Назначение**: Источник вакансий (поиск в реальном времени)
- **Функции**:
  - Поиск вакансий по параметрам
  - Получение описаний вакансий
  - Ограничение: 2000 вакансий за запрос

## Процесс формирования профиля позиции

### Шаг 1: Создание профиля позиции (Карьерный консультант)
1. **Карьерный консультант** заходит в Web Application
2. **Заполняет форму профиля позиции**:
   - Название позиции (например: "Java-разработчик")
   - Специальность (Java, Python, аналитик и др.)
   - Навыки (Spring Boot, Hibernate, PostgreSQL и др.)
   - Опыт (в годах)
   - Зарплата (от и до)
   - Город
   - Тип занятости (полная, частичная, удаленная)
3. **Сохраняет профиль** → данные записываются в PostgreSQL через Profile Service

### Шаг 2: Назначение профиля уходящему сотруднику
1. **Карьерный консультант** назначает профиль позиции уходящему сотруднику
2. **Уходящий сотрудник** получает доступ к профилю

### Шаг 3: Поиск вакансий (Уходящий сотрудник)
1. **Уходящий сотрудник** заходит в Web Application
2. **Выбирает профиль позиции** из списка доступных
3. **Нажимает кнопку "Найти вакансии"**

### Шаг 4: Формирование запроса к HH.ru
1. **Search Service** получает профиль позиции
2. **Отправляет профиль в DeepSeek API** для преобразования в параметры для HH.ru
3. **DeepSeek API** возвращает структурированные параметры:
   ```json
   {
     "text": "Java разработчик Spring Boot",
     "area": [1],
     "experience": "between3And6",
     "salary_from": 150000,
     "salary_to": 250000,
     "employment": "full"
   }
   ```

### Шаг 5: Поиск вакансий на HH.ru
1. **Search Service** отправляет запрос к HH.ru API с параметрами
2. **HH.ru API** возвращает список вакансий (до 2000)
3. **Search Service** нормализует данные

### Шаг 6: Генерация эмбеддингов
1. **Search Service** генерирует эмбеддинг для профиля позиции через Embedding Engine
2. **Search Service** генерирует эмбеддинги для каждой вакансии через Embedding Engine
3. **Кэширует эмбеддинги** в Redis

### Шаг 7: Семантическое ранжирование
1. **Search Service** сравнивает эмбеддинг профиля с эмбеддингами вакансий (косинусное сходство)
2. **Ранжирует вакансии** по степени соответствия (процентное соответствие)
3. **Формирует топ-N результатов** (например, топ-50)

### Шаг 8: Сохранение результатов
1. **Search Service** сохраняет результаты в PostgreSQL (таблица `search_results`)
2. **Кэширует результаты** в Redis для ускорения повторных запросов

### Шаг 9: Отображение результатов
1. **Search Service** возвращает результаты в API Gateway
2. **API Gateway** передает результаты в Web Application
3. **Web Application** отображает список вакансий с процентным соответствием
4. **Уходящий сотрудник** видит релевантные вакансии

## Связи между контейнерами

### Входящие связи
- Карьерный консультант → Web Application (HTTPS)
- Уходящий сотрудник → Web Application (HTTPS)

### Внутренние связи
- Web Application → API Gateway (POST /api/search, POST /api/profile, HTTPS/REST)
- API Gateway → Search Service (REST)
- API Gateway → Profile Service (REST)
- Search Service → Embedding Engine (in-process)
- Search Service → Redis (TCP)
- Profile Service → PostgreSQL (TCP)
- API Gateway → PostgreSQL (TCP)
- API Gateway → Redis (TCP)

### Внешние связи
- Search Service → DeepSeek API (HTTPS)
- Search Service → HH.ru API (HTTPS)

## Преимущества MVP схемы (v2)

### Для junior-разработчиков
- ✅ **Простая реализация**: Минимум компонентов
- ✅ **Быстрый старт**: Streamlit + FastAPI + Python
- ✅ **Легко отлаживать**: Все сервисы на Python
- ✅ **Минимум зависимостей**: Только Python библиотеки + PostgreSQL + Redis

### Для проекта
- ✅ **Хранение данных**: PostgreSQL для持久化
- ✅ **Кэширование**: Redis для ускорения
- ✅ **Процесс формирования профиля**: Карьерный консультант создает профиль, уходящий сотрудник использует
- ✅ **Масштабируемость**: Легко добавить компоненты позже

## Недостатки MVP схемы (v2)

### Ограничения
- ❌ **Один процесс Search Service**: Ограничение по масштабированию
- ❌ **Нет fallback**: Нет механизма при отказе DeepSeek API
- ❌ **Нет мониторинга**: Нет логирования и метрик

### Риски
- **Производительность**: При большом количестве пользователей может не хватить ресурсов
- **Отказоустойчивость**: Нет fallback механизмов

## Следующие шаги после MVP

1. **Добавить fallback**: На случай отказа DeepSeek API
2. **Разделить сервисы**: Выделить Vectorization Service, Caching Service
3. **Добавить мониторинг**: Логирование, метрики
4. **Добавить аутентификацию**: JWT, OAuth 2.0
5. **Добавить администрирование**: Панель для карьерного консультанта
