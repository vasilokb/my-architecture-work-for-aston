# Контейнерная диаграмма - MVP поиска вакансий для уходящих сотрудников (v3 с учетом справочников HH.ru)

## Описание MVP

Простая система для карьерного консультанта: он создает профиль позиции (даже я EM запомню, что добавляю) и получает релевантные вакансии с HH.ru. Вся логика построена на использовании справочников HH.ru (города, специализации, опыт, график) и LLM‑шлюза OpenRouter. Анкеты уходящих сотрудников и CV не загружаются; выбор происходит по специальностям и умениям через выпадающие списки.

## Совпадение с схемой в PlantUML

На основе схемы PlantUML в `mvp-container-v3.puml`:

- **Карьерный консультант** создает профиль позиции через Web Application.
- **Web Application (Streamlit)** служит интерфейсом с выпадающими списками для выбора города, специализации и других параметров из справочников HH.ru.
- **API Gateway (FastAPI)** маршрутизирует запросы к профилям, поиску и справочникам.
- **Profile Service (Python/FastAPI)** отвечает за CRUD профилей позиций и валидацию по справочникам (город, график) через Dictionary Service.
- **Search Service (Python/FastAPI)** формирует URL для HH.ru API, вызывает OpenRouter для LLM‑обработки, выполняет поиск вакансий и сохраняет результаты.
- **Dictionary Service (Python/FastAPI)** кэширует справочники HH.ru (areas, experience, schedule) и предоставляет их для UI и валидации.
- **PostgreSQL** хранит профили позиций, историю поисков и снимки вакансий.
- **Redis** используется как кэш справочников и результатов поиска.

## Контейнеры системы и их роли

### 1. Web Application (Streamlit)
- **Технология**: Streamlit
- **Назначение**: HR‑интерфейс для карьерного консультанта
- **Функции**:
  - Форма создания профиля позиции с выпадающими списками (города, специализации, опыт, график)
  - Отображение списка вакансий и истории поисков
- **Преимущества**:
  - Простая реализация (Python)
  - Быстрый старт
  - Удобные компоненты для выпадающих списков

### 2. API Gateway (FastAPI)
- **Технология**: FastAPI
- **Назначение**: Маршрутизация запросов между сервисами
- **Функции**:
  - Принимает запросы от Web Application
  - Передает запросы в Profile Service, Search Service и Dictionary Service

### 3. Profile Service (Python/FastAPI)
- **Технология**: Python/FastAPI
- **Назначение**: Управление профилями позиций
- **Функции**:
  - CRUD профилей позиций
  - Валидация выбранных параметров по справочникам (через Dictionary Service)
  - Сохранение в PostgreSQL

### 4. Search Service (Python/FastAPI)
- **Технология**: Python/FastAPI
- **Назначение**: Основной поиск и обработка вакансий
- **Функции**:
  - Формирование запроса к HH.ru API (URL из параметров)
  - Получение вакансий через GET /vacancies
  - Вызов OpenRouter API для LLM‑обработки профиля и уточнения параметров
  - Кэширование результатов в Redis
  - Сохранение истории поиска и снимков вакансий в PostgreSQL

### 5. Dictionary Service (Python/FastAPI)
- **Технология**: Python/FastAPI
- **Назначение**: Кэширование справочников HH.ru
- **Функции**:
  - Периодическое обновление справочников areas и dictionaries из HH.ru API (GET /areas, GET /dictionaries)
  - Сохранение справочников в Redis
  - Предоставление справочных данных Profile Service и Search Service для маппинга названий в ID

### 6. PostgreSQL
- **Технология**: PostgreSQL
- **Назначение**: Хранилище данных
- **Таблицы**:
  - `position_profiles`: профили позиций (название, специальность, опыт, зарплата, город и др.)
  - `search_history`: история поисков и снимков вакансий

### 7. Redis
- **Технология**: Redis
- **Назначение**: Кэш
- **Функции**:
  - Кэш справочников HH.ru (areas, experience, schedule)
  - Кэш результатов поиска для ускорения повторных запросов

## Внешние системы

- **OpenRouter API**: LLM‑шлюз для интерпретации профиля позиции и формирования параметров запроса к HH.ru.
- **HH.ru API**: источник вакансий и справочников (areas, directories, experience, schedule и др.).

## Связи и последовательность шагов

1. Карьерный консультант создает профиль через Web Application.
2. Web Application отправляет запрос на API Gateway.
3. API Gateway перенаправляет в Profile Service и Search Service.
4. Profile Service валидирует данные через Dictionary Service перед сохранением в PostgreSQL.
5. Dictionary Service забирает справочники из HH.ru API и кэширует их в Redis.
6. Search Service формирует запрос к HH.ru API, использует справочники для маппинга названий в ID, получает вакансии и сохраняет результаты в PostgreSQL.
7. Search Service использует OpenRouter для LLM‑обработки и запросов к HH.ru API.

## Преимущества для junior‑разработчиков

- архитектура ограничена несколькими контейнерами на Python;
- работа с выпадающими списками и справочниками HH.ru упрощает процесс согласования и валидации данных;
- кэширование справочников и результатов поиска снижает нагрузку на HH.ru API и ускоряет работу интерфейса.
