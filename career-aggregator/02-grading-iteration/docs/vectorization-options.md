# Варианты реализации векторизации для Career Aggregator System

## Ограничения проекта
- **Оперативная память**: 1 ГБ
- **Разработчики**: Junior-специалисты (Python)
- **Бюджет**: Ограниченный

## Какие вектора кэшируются?

### 1. Вектора запросов пользователей
- **Что это**: Векторное представление текстового запроса пользователя (специальность + навыки + параметры)
- **Зачем кэшировать**: При повторном запросе с теми же параметрами не нужно векторизировать заново
- **Ключ кэша**: Хэш текста запроса (например: `vector:query:abc123`)
- **TTL**: 24 часа (или до изменения профиля пользователя)

### 2. Вектора вакансий
- **Что это**: Векторное представление описания вакансии
- **Зачем кэшировать**: При повторном запросе не нужно векторизировать одну и ту же вакансию заново
- **Ключ кэша**: ID вакансии (например: `vector:vacancy:12345`)
- **TTL**: 7 дней (или до обновления вакансии)

### 3. Результаты поиска (опционально)
- **Что это**: Список вакансий с процентным соответствием для конкретного запроса
- **Зачем кэшировать**: При повторном запросе с теми же параметрами не нужно делать поиск заново
- **Ключ кэша**: Хэш запроса (например: `search:results:abc123`)
- **TTL**: 1 час (или до появления новых вакансий)

## Преимущества кэширования векторов
- ✅ Снижение нагрузки на векторизацию (локальную или внешнюю)
- ✅ Ускорение повторных запросов
- ✅ Экономия ресурсов (память, CPU, API запросы)
- ✅ Улучшение用户体验 (быстрый ответ)

## Вариант 1: Внешние LLM API (OpenRouter)

### Описание
Использование внешних LLM API для векторизации запросов и вакансий. Не требует локальных вычислительных ресурсов.

### Технологии
- **OpenRouter API**: Агрегатор множества LLM моделей (GPT, Claude, LLaMA и др.)
- **Бесплатные модели**: Есть бесплатные модели с ограничениями
- **REST API**: Простой HTTP-интерфейс

### Как работает
1. **Vectorization Service** получает текстовый запрос
2. **Отправляет запрос** в OpenRouter API
3. **Получает вектор** (эмбеддинг) от LLM модели
4. **Возвращает вектор** для дальнейшего использования

### Преимущества
- ✅ Не требует локальных ресурсов (память, CPU)
- ✅ Простая реализация (REST API)
- ✅ Доступ к мощным моделям
- ✅ Легко масштабируется

### Недостатки
- ❌ Зависимость от интернета
- ❌ Зависимость от внешнего сервиса
- ❌ Возможные задержки (сеть)
- ❌ Ограничения бесплатных моделей (rate limits)
- ❌ Потенциальные расходы при превышении лимитов

### Риски
- **Отказ сервиса**: OpenRouter может быть недоступен
- **Изменение API**: API может измениться
- **Ограничения**: Бесплатные модели имеют лимиты на запросы

### Рекомендации для MVP
- ✅ Подходит для MVP и прототипирования
- ✅ Быстрый старт без сложной настройки
- ⚠️ Нужен fallback механизм на случай отказа

## Вариант 2: Легковесные библиотеки для эмбеддингов (sentence-transformers)

### Описание
Использование локальных библиотек для создания эмбеддингов. Работает офлайн, требует минимум ресурсов.

### Технологии
- **sentence-transformers**: Библиотека для создания эмбеддингов
- **Модели**: all-MiniLM-L6-v2 (80 МБ), paraphrase-MiniLM-L3-v2 (60 МБ)
- **PyTorch**: Легковесная версия для инференса

### Как работает
1. **Установка модели**: Скачивается один раз (~80 МБ)
2. **Vectorization Service** загружает модель в память
3. **При запросе**: Текст преобразуется в вектор локально
4. **Вектор сохраняется** для повторного использования

### Требования к ресурсам
- **Память**: 200-500 МБ (в зависимости от модели)
- **Диск**: 80-200 МБ для модели
- **CPU**: Стандартный (нетребовательный)

### Преимущества
- ✅ Работает офлайн (нет зависимости от интернета)
- ✅ Быстро (локальный инференс)
- ✅ Минимальные требования к ресурсам
- ✅ Бесплатно (нет расходов на API)
- ✅ Предсказуемость (нет внешних зависимостей)

### Недостатки
- ❌ Менее мощные модели (по сравнению с GPT-4)
- ❌ Нужно скачивать и обновлять модели
- ❌ Ограниченные возможности (только эмбеддинги, не генерация текста)

### Риски
- **Качество эмбеддингов**: Может быть хуже, чем у мощных моделей
- **Обновление моделей**: Нужно вручную обновлять

### Рекомендации для MVP
- ✅ Отлично подходит для MVP
- ✅ Простая реализация
- ✅ Нет внешних зависимостей
- ⚠️ Качество эмбеддингов может быть недостаточным для сложных запросов

## Вариант 3: Комбинированный подход (sentence-transformers + OpenRouter)

### Описание
Комбинация локальных эмбеддингов и внешних LLM API для баланса между производительностью и надежностью.

### Технологии
- **sentence-transformers**: Основной метод векторизации
- **OpenRouter API**: Fallback при ошибках локальной векторизации
- **Redis**: Кэширование векторов

### Как работает
1. **Vectorization Service** получает текстовый запрос
2. **Попытка локальной векторизации** через sentence-transformers
3. **Если успешно** → возвращает вектор
4. **Если ошибка** → отправляет запрос в OpenRouter API
5. **Кэширует результат** в Redis для повторного использования

### Алгоритм fallback
```python
def vectorize(text: str) -> list[float]:
    # Попытка 1: Локальная векторизация
    try:
        vector = local_model.encode(text)
        cache.set(f"vector:{hash(text)}", vector)
        return vector
    except Exception as e:
        logger.warning(f"Local vectorization failed: {e}")
    
    # Попытка 2: OpenRouter API
    try:
        vector = openrouter_api.embed(text)
        cache.set(f"vector:{hash(text)}", vector)
        return vector
    except Exception as e:
        logger.error(f"OpenRouter failed: {e}")
        raise VectorizationError("All vectorization methods failed")
```

### Преимущества
- ✅ Быстрый локальный инференс (основной путь)
- ✅ Отказоустойчивость (fallback на внешний API)
- ✅ Минимальные расходы (используем бесплатные модели)
- ✅ Работает офлайн (если локальная модель доступна)
- ✅ Кэширование снижает нагрузку

### Недостатки
- ❌ Сложнее реализация (два метода векторизации)
- ❌ Нужно поддерживать два механизма
- ❌ Возможны задержки при fallback

### Риски
- **Сложность**: Больше кода для поддержки
- **Тестирование**: Нужно тестировать оба пути

### Рекомендации для MVP
- ✅ Рекомендуется для production
- ✅ Баланс между производительностью и надежностью
- ⚠️ Можно начать с Варианта 2, затем добавить fallback

## Рекомендация

Для вашего проекта с ограничением в 1 ГБ памяти и junior-разработчиками рекомендуется:

### Для MVP (первый этап)
**Вариант 2: sentence-transformers**
- Простая реализация
- Нет внешних зависимостей
- Быстрый старт

### Для production (второй этап)
**Вариант 3: Комбинированный подход**
- Добавить fallback на OpenRouter
- Повысить отказоустойчивость
- Минимизировать расходы

### Порядок реализации
1. **Этап 1**: Реализовать Вариант 2 (sentence-transformers)
2. **Этап 2**: Протестировать качество эмбеддингов
3. **Этап 3**: При необходимости добавить fallback на OpenRouter
4. **Этап 4**: Оптимизировать кэширование
