**Развёрнутое обоснование «вьюхи вместо API» (уровень ADR):**
- **Цена:** API — разработка сервиса на стороне Цербера, недели их времени
  при том, что мы не управляем их приоритетами; вьюхи — доработка схемы
  за часы
- **Сценарий:** API силён для интерактивных запросов и внешних потребителей;
  у нас ночной батч одного процесса — квоты и рантайм-авторизация не дают
  ценности
- **Контракт и изоляция:** вьюхи дают те же — фиксированная схема, read-only,
  одно подключение
- **Защита от переделки:** источник абстрагирован адаптером; переход
  «вьюхи → API» затронет только его реализацию, пайплайн и матчинг
  не изменятся

**Требования к Церберу:** плоские вьюхи; поле времени сбора для инкремента
(published_at не подходит — это дата публикации на HH, а не попадания в их
базу); развитие без ломки контракта (новые колонки или версия);
безопасность рабочей эксплуатации: сервисная учётка только SELECT, приём
с наших IP, SSL, лимит соединений (достаточно двух) и таймауты.
**С нашей стороны:** одно подключение, фоновый процесс, ночное окно,
никакой записи.
