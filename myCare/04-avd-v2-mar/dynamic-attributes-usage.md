# Использование динамических атрибутов в расчётах фабрики страховых продуктов

## Обзор

Динамические атрибуты (EAV-модель) позволяют добавлять произвольные параметры к сущностям (продуктам, покрытиям, факторам тарификации) без изменения схемы БД. Эти атрибуты могут использоваться в расчётах страховой премии, проверках применимости продукта, формировании документов и других бизнес-процессах.

## Как работают динамические атрибуты

### 1. Структура данных

- **`dynamic_attribute`** – метаданные атрибута (код, название, тип данных, сущность, обязательность, валидация).
- **`entity_attribute_value`** – значения атрибутов для конкретных экземпляров сущностей.
- **`attribute_validation`** – правила валидации значений.
- **`attribute_group`** – группировка атрибутов для UI.

### 2. Примеры атрибутов для разных сущностей

| Сущность | Код атрибута | Тип | Назначение | Использование в расчётах |
|----------|--------------|-----|------------|--------------------------|
| `PRODUCT_TEMPLATE` | `min_age` | NUMBER | Минимальный возраст застрахованного | Проверка применимости продукта |
| `PRODUCT_TEMPLATE` | `max_coverage_amount` | NUMBER | Максимальная сумма страхования | Ограничение при расчёте премии |
| `PRODUCT_TEMPLATE` | `required_documents` | JSON | Список требуемых документов | Формирование требований для оформления |
| `COVERAGE` | `territorial_restrictions` | JSON | Географические ограничения | Проверка территории риска |
| `COVERAGE` | `waiting_period_days` | NUMBER | Период ожидания | Расчёт начала действия покрытия |
| `PRICING_FACTOR` | `validation_rules` | JSON | Правила валидации значений | Проверка корректности введённых данных |
| `PRICING_FACTOR` | `depends_on_other_factor` | BOOLEAN | Зависимость от другого фактора | Условный расчёт премии |

### 3. Процесс расчёта с использованием динамических атрибутов

**Сценарий:** Расчёт страховой премии для продукта «КАСКО» с учётом динамических параметров.

#### Шаг 1: Загрузка атрибутов продукта

При получении запроса на расчёт (`quote_request`) система:
1. Определяет `product_template_id` и `program_template_id`.
2. Загружает все динамические атрибуты для этих сущностей из `entity_attribute_value`.
3. Преобразует их в структурированный объект для использования в бизнес-логике.

```sql
SELECT da.attribute_code, eav.string_value, eav.number_value, eav.boolean_value, eav.date_value, eav.json_value
FROM entity_attribute_value eav
JOIN dynamic_attribute da ON da.id = eav.attribute_id
WHERE eav.entity_type = 'PRODUCT_TEMPLATE'
  AND eav.entity_id = :product_template_id;
```

#### Шаг 2: Применение атрибутов в проверках

Например, продукт имеет атрибут `min_age = 18`. При расчёте проверяется возраст застрахованного:
```python
if insured_age < product_attributes['min_age']:
    raise ValidationError('Возраст застрахованного меньше минимального')
```

#### Шаг 3: Использование в тарифной модели

Динамические атрибуты могут влиять на коэффициенты тарификации. Например, атрибут `territorial_restrictions` покрытия может содержать JSON с коэффициентами для разных регионов:
```json
{
  "MOSCOW": 1.2,
  "SPB": 1.1,
  "OTHER": 1.0
}
```

Сервис расчёта (`PricingService`) использует этот коэффициент при вычислении премии:
```python
region_coefficient = coverage_attributes['territorial_restrictions'].get(insured_region, 1.0)
premium = base_premium * region_coefficient
```

#### Шаг 4: Учёт в факторах тарификации

Факторы тарификации (`pricing_factor`) могут иметь динамические атрибуты, например `validation_rules`, которые описывают допустимые диапазоны значений. При расчёте система проверяет соответствие введённых значений этим правилам.

### 4. Пример полного цикла расчёта

1. **Клиент** выбирает продукт «КАСКО» для автомобиля в Москве.
2. **Система** загружает продукт и его динамические атрибуты:
   - `min_age = 18`
   - `max_coverage_amount = 5000000`
   - `territorial_restrictions = {"MOSCOW": 1.2}`
3. **Проверка применимости**: возраст клиента 25 → проходит, сумма страхования 3 млн → проходит.
4. **Расчёт премии**: базовая ставка 100 000 ₽, коэффициент территории 1.2 → итого 120 000 ₽.
5. **Формирование результата**: премия фиксируется в `quote_result`, использованные атрибуты сохраняются в `coverage_breakdown` (JSON) для аудита.

### 5. Преимущества подхода

- **Гибкость**: Новые параметры добавляются через админку без программирования.
- **Аудируемость**: Все использованные атрибуты сохраняются в расчёте.
- **Многоразовость**: Один атрибут может применяться к множеству сущностей.
- **Валидация**: Централизованные правила проверки данных.

### 6. Ограничения и рекомендации

- **Производительность**: EAV-модель может замедлять запросы при большом количестве атрибутов. Рекомендуется кэширование.
- **Сложность запросов**: Для сложных расчётов может потребоваться денормализация или materialized views.
- **Консистентность**: Изменение атрибута после создания расчёта не должно влиять на исторические данные.

## Заключение

Динамические атрибуты обеспечивают необходимую гибкость для страховой фабрики, позволяя быстро адаптироваться к изменениям регуляторных требований и рыночных условий. Они интегрируются в процесс расчёта через стандартные точки расширения: проверки применимости, тарифные коэффициенты, валидацию данных и формирование документов.

Для реализации рекомендуется:
1. Создать административный интерфейс для управления атрибутами.
2. Разработать сервис для загрузки и применения атрибутов в расчётах.
3. Добавить логирование использования атрибутов для отладки и аудита.
4. Оптимизировать запросы через кэширование и индексы.
