## Состав папок

### 01-as-is-dec — AS-IS-анализ доменов (декабрь)
Доменные описания страховых направлений: `auto-insurance.md`,
`dms-insurance.md`, `property-insurance.md`, `travel-insurance.md`,
`aviation-service.md`, `employee-service.md`; `infra.md`;
диаграммы `as-is.puml`, `adult-с1.puml`, `core.puml`.

### 02-product-factory — фабрика продуктов
`product-factory.md` (концепция) + контейнерная `.puml` + классовая
`-class.puml` + ER-модели `-er.puml` и `-er-flexible.puml` (гибкая модель
с динамическими атрибутами — связка с `dynamic-attributes-usage.md`).

### 03-as-is-gpt-iterations — итерации AS-IS с ИИ-ассистентом
8 версий диаграмм за 4 дня (27–30.12): от черновика 27122025 до
as-is-detailed. Метод: AS-IS строился по дампу дерева реальных репозиториев
(в источнике `gpt/str.md`, 230 КБ, 4784 строки — не копирован из-за
повреждённой кодировки; структура включает authorization-server, compose,
helm и др. — видно объём проанализированной кодовой базы).

### 04-avd-v2-mar — целевая архитектура v2.0 (март)
`c4.puml → c4-5.puml` — 5 итераций C4-контейнеров (10–13.03);
`description.md` — детализация ключевых элементов: **PDP Service**
(ABAC/RBAC без XACML — «команда не знает XACML»; PEP в API Gateway;
политики в PostgreSQL; кэш решений в Redis), **Audit Service**
(Kafka → Elasticsearch), **CDC Processor** (захват изменений → Kafka);
`1.md` — **Lightweight AVD v2.0** (866 строк: персоны, зоны, контейнеры);
`avd-light-rules.md` — **собственный стандарт оформления Lightweight AVD**
(философия «80% ценности за 20% усилий», целевые аудитории, правила);
`1.puml`, `2.puml`, `dynamic-attributes-usage.md`.

## Что доказывает пакет

1. **Темп:** 6 доменных описаний (~93 КБ текста) + 3 диаграммы за 3 дня
   (09–11.12); 8 итераций AS-IS за 4 дня; 4 итерации C4 за один день
   (10.03) + пятая и детализация к 13.03; AVD v2.0 + собственный стандарт
   к 21.03.
2. **Методология:** стандарт Lightweight AVD — воспроизводимый шаблон
   для всей команды («стартовый шаблон / шпаргалка / вход для ADR, US, FDD»);
   итеративная доводка диаграмм (v1→v5, восемь AS-IS-версий).
3. **Работа с ИИ-ассистентом:** декабрьские gpt-итерации и мартовское
   description.md — применение LLM для ускорения архитектурной
   документации при сохранении контроля (правила формата задаются явно).
4. **Глубина домена:** шесть страховых направлений разобраны отдельно;
   фабрика продуктов доведена до классовой модели и гибкой ER.
5. **Сквозная экспертиза:** PDP/ABAC, CDC, audit — темы, продолженные
   затем в Эвергрине (C1, C2, C6) — преемственность тех же решений
   в банковском домене.
