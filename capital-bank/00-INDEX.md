## Структура аудита (v2, 816 строк)

1. **Разбор всех НФТ команды по категориям** с оценкой качества формулировок:
   - PER-1…12 (производительность): найдены дубли (PER-1/PER-2), нереалистичный
     KPI (PER-9: «внутренние API ≤500 мс» — «нужно мерить end-to-end, а не хопы»),
     пункты, не являющиеся НФТ (PER-10…12 — правила реализации)
   - SEC-1…15: пробелы — нет Anti-Fraud, нет численных требований к ревокации
   - SAF-1…9: критичный пробел — нет требования иммутабельности аудита
   - AVL/ROB: AVL-1 (99,9%) «архитектурно не обеспечивается»
2. **Сравнение с зрелыми банками** (таблицы по 6 осям): роль Core, продуктовый
   слой, стиль интеграции, Bounded Contexts, CQRS, владение данными
3. **Количественный профиль**: расчёт реалистичной ёмкости — 15–35 тыс.
   клиентов, ~20 тыс. операций/сутки, пик 8–12 оп/с (из DAU 20% × 2 операции)
4. **10 сценариев атрибутов качества** в SEI-формате (стимул → артефакт →
   окружение → обработка → измеримая метрика): пиковые платежи, отказ БД ABS,
   потеря событий Kafka, рост до 100 тыс. клиентов, вывод средств с валидным
   токеном, GraphQL-перегрузка, RTO/RPO...
5. **Ключевые риски для руководства** (7 пунктов: SPoF ABS, продуктовый
   монолит, нет CQRS/BC, Observability, GraphQL-DoS, нет Anti-Fraud,
   мутируемый аудит)
6. **План трансформации** (high-level): горячий резерв ABS + витрины чтения,
   доменная декомпозиция + CQRS, Observability-контур, Anti-Fraud,
   Transaction Outbox + иммутабельный Audit Journal

## Что доказывает пакет

1. **Скорость:** встреча → финальный аудит за 72 часа; объём — 816 строк
   структурированного анализа.
2. **Методология уровня Enterprise-аудита:** сценарии качества в SEI-формате
   (Stimulus-Environment-Response-Measure), проверка качества самих НФТ
   (не только архитектуры), количественная модель ёмкости с прозрачными
   допущениями, сравнение с отраслевой зрелостью.
3. **Диагноз без страховки:** «распределённый монолит», «AVL-1 архитектурно
   не обеспечивается», «время обнаружения инцидента не ограничено» —
   формулировки, за которые платят внешние аудиторы.
4. **Конструктивность:** каждому риску — направление трансформации;
   «адекватна учебному MVP и небольшой розничной платформе» — оценка
   по масштабу, а не абстрактно.
5. **Сквозная линия базы:** тот же SEI-аппарат, что в sql-trainer
   (04-architecture-doc: атрибуты качества), тот же диагноз «распределённый
   монолит», что в Investment (INFRASTRUCTURE-AUDIT), те же темы
   Observability/Outbox/CQRS — единая методология через все темы.
6. **Позиция в хронологии базы:** 29.11–01.12.2025 — между sql-trainer
   (окт–дек) и Эвергрином (с 25.12): плотный безостановочный ноябрь.
