# Учебное руководство для стажеров-аналитиков: Модуль учёта операций и проводок АБС

## **РАЗДЕЛ 1: БАЗОВОЕ ПОНИМАНИЕ**

**Что это за модуль?**
Это "двигатель" бухгалтерского учёта банка, который фиксирует все финансовые операции: переводы, платежи, списания, зачисления. Если модуль счетов отвечает за "кошельки", то этот модуль — за "чеки" и "платежные поручения", которые двигают деньги между кошельками. Он превращает фактические действия (клиент перевёл деньги) в бухгалтерские записи.

**Какие бизнес-потребности закрывает?**
1.  **Юридическое отражение операций:** Каждая копейка должна быть учтена по правилам ЦБ и МСФО.
2.  **Контроль ликвидности:** Система следит, чтобы со счёта не списали больше, чем на нём есть (с учётом резервов).
3.  **Формирование отчётности:** Все проводки — сырьё для баланса, отчёта о прибылях и убытках, кассового плана.
4.  **Автоматизация рутинных операций:** Массовые начисления процентов, комиссий проходят через этот модуль.

**Кто основные пользователи?**
*   **Сотрудники банка (внутренние):** Бухгалтеры, кассиры, операционисты, сотрудники казначейства, аналитики.
*   **Клиенты (опосредованно):** Через выписки и статусы операций.
*   **Регуляторы (опосредованно):** Через обязательную отчётность, которая формируется на основе проводок.

**Интеграция с изученными модулями:**
*   **С модулем "Клиенты":** Каждая проводка, связанная с клиентским счётом, ссылается на договор и клиента. Это нужно для аналитики: "Какой клиент принёс доход?".
*   **С модулем "Счета":** Проводка всегда затрагивает как минимум два счёта: откуда и куда. Модуль счетов предоставляет информацию об остатках, валюте, статусе счёта для проведения проверок перед операцией.

## **РАЗДЕЛ 2: КЛЮЧЕВЫЕ СУЩНОСТИ И ПОНЯТИЯ**

**1. Проводка (транзакция)**
*   **Суть:** Запись об изменении остатка на счёте. В банковском учёте проводка всегда **парная**: одна сумма списывается с одного счёта и зачисляется на другой.
*   **Атрибуты:** Дата учёта, дата операции, сумма, валюта, счёт дебета, счёт кредита, уникальный номер, код типа операции, статус, ссылка на документ-основание.
*   **Важное различие:**
    *   **Полупроводка:** Техническая запись только по одному счёту (либо дебет, либо кредит). Нужна для внутренней работы системы.
    *   **Парная проводка:** Две логически связанные полупроводки, которые видны в отчётности. Процесс их соединения называется **линковкой**.

**2. Холд (резерв)**
*   **Суть:** "Замораживание" части средств на счёте под будущую операцию. Уменьшает доступный для списания остаток, но не изменяет фактический.
*   **Аналогия:** Бронирование номера в отеле. Деньги на карте "заморожены", но не списаны, пока вы не заселитесь.
*   **Атрибуты:** Сумма, дата начала, дата окончания, причина резервирования, статус (активный/неактивный).

**3. Конверсионная операция**
*   **Суть:** Операция обмена одной валюты на другую. В бухгалтерии отражается несколькими связанными проводками через специальные технические счета, а также может включать проводку по курсовой разнице (доход/расход банка от изменения курса).

**4. Корректирующая проводка**
*   **Суть:** Исправительная запись, которая вносится задним числом. Используется для исправления ошибок в уже закрытых операционных днях.
*   **Важно:** Её ввод запускает автоматический пересчёт всех зависимых данных (переоценку, проценты) за весь период с даты ошибки.

**5. Символ кассового плана**
*   **Суть:** Код, который "прикрепляется" к кассовой операции (приход/расход наличных) для целей составления отчётности в ЦБ (например, отчёт о кассовых оборотах).

## **РАЗДЕЛ 3: ДЕТАЛЬНЫЕ ПРОЦЕССЫ**

### **Процесс 1: Установка холда (резерва)**
*   **Кто инициирует:** Сотрудник операционного отдела или автоматизированный модуль (например, кредитный).
*   **Шаги:**
    1.  Пользователь выбирает счёт и указывает сумму резерва, причину и сроки.
    2.  Система проверяет, достаточно ли доступного остатка на счёте (фактический остаток минус уже установленные холды).
    3.  Если проверка пройдена, система создаёт запись о холде в специальной таблице и одномоментно уменьшает доступный остаток по счёту.
    4.  Холд становится активным с указанной даты.
*   **Проверки:** Существование счёта, его статус, наличие средств, корректность кода причины.
*   **Ошибки:** "Недостаточно средств", "Неверный код причины резерва". Обработка — отмена операции с сообщением пользователю.

### **Процесс 2: Ввод стандартной платежной проводки (перевод)**
*   **Кто инициирует:** Операционист (вручную) или система (автоматически из платежного документа).
*   **Шаги:**
    1.  **Ввод данных:** Указываются счёт дебета (откуда), счёт кредита (куда), сумма, дата валютирования, тип операции, реквизиты плательщика/получателя, назначение платежа.
    2.  **Комплекс проверок (валидация):**
        *   Формальные: Корректность номеров счетов, соответствие валюты счетов.
        *   Бизнес-правила: Проверка доступного остатка (с учётом холдов) на счёте списания. Проверка "не выходит ли счёт в минус" в зависимости от типа счёта и операции.
        *   Контроль доступа: Имеет ли пользователь право проводить операции по данным счетам.
    3.  **Проведение:** Если все проверки пройдены, система в режиме единой транзакции:
        *   Создает две полупроводки (дебет и кредит).
        *   Обновляет остатки на счетах.
        *   Создает запись в журнале парных проводок.
        *   Записывает дополнительную информацию (реквизиты документа).
    4.  **Линковка:** Для отчётности система автоматически связывает две полупроводки в одну парную проводку.
*   **Создаваемые документы:** Мемориальный ордер (внутренний бухгалтерский документ), выписка по счёту.
*   **Пример:** Перевод зарплаты на карту сотрудника. Дебетуется счёт банка "Расчеты с персоналом", кредитуется карточный счёт сотрудника.

### **Процесс 3: Конвертация валюты**
*   **Кто инициирует:** Клиент (через заявку) или казначейство банка.
*   **Особенность:** Нельзя сделать прямую проводку RUB->USD, так как счета в разных валютах. Используется схема с техническими счетами.
*   **Базовая схема шагов (продажа USD за RUB):**
    1.  Списание USD с клиентского счёта. Зачисление USD на технический валютный счёт.
    2.  Зачисление RUB на клиентский рублёвый счёт. Списание RUB с технического рублёвого счёта.
    3.  **Расчёт и отражение курсовой разницы:** Из-за разницы курсов возникает рублёвый дисбаланс. Система рассчитывает его и проводит отдельную проводку на счёт доходов/расходов банка.
*   **Ключевая проверка:** Контроль целостности — рублёвые эквиваленты всех частей операции должны сойтись.

## **РАЗДЕЛ 4: ЖИЗНЕННЫЙ ЦИКЛ ДАННЫХ**

*   **Создание:** Данные создаются при вводе операций (вручную, автоматически из других систем, пакетной загрузкой из файлов).
*   **Изменение:** Прямое изменение уже учтённой проводки **невозможно**. Для исправления используются:
    1.  **Корректирующая проводка** (задним числом).
    2.  **Сторно:** Ввод обратной проводки в текущем дне для отмены ошибочной.
*   **Архивация/Закрытие дня:** В конце операционного дня запускается процедура "закрытия дня". Проводки текущего дня становятся неизменяемыми, по ним формируются окончательные итоги, данные переносятся в отчёты. Начинается новый рабочий день.
*   **Хранение истории:** История изменений самих проводок не ведётся (они неизменяемы после проведения), но ведётся:
    *   История удалений (какие проводки и когда были удалены в течение дня).
    *   История корректировок (журнал корректирующих проводок).
    *   Архив закрытых дней.

## **РАЗДЕЛ 5: ИНТЕГРАЦИИ С ДРУГИМИ СИСТЕМАМИ**

*   **С системой расчетов (СР):** Это ключевая интеграция. СР готовит платёжные документы, а модуль проводок исполняет их, создавая фактические бухгалтерские записи. Данные: реквизиты платежа, суммы, счета.
*   **С тарифным и процентным модулями:** Эти модули рассчитывают суммы комиссий и процентов, а затем инициируют в модуле проводок их автоматическое списание/начисление.
*   **С системой формирования отчётности (БИ):** Модуль проводок — главный поставщик сырых данных. Все проводки с определёнными признаками (код дохода, центр прибыли) передаются в BI для анализа.
*   **Формат обмена:** Чаще всего используется пакетная выгрузка/загрузка через файлы определённого формата или вызов внутренних программных интерфейсов (API) системы.
*   **Типичные проблемы:** Расхождение в остатках между системами (например, в СР и АБС), ошибки формата файла при пакетной загрузке, задержки в обмене, приводящие к неактуальным данным.

## **РАЗДЕЛ 6: КОНТРОЛЬ И БЕЗОПАСНОСТЬ**

*   **Контроль доступа:**
    *   **Ролевая модель:** Доступ к вводу, просмотру, изменению операций разграничен. Кассир не может проводить межбанковские платежи, а бухгалтер — кассовые операции.
    *   **Привязка к отделению/исполнителю:** Сотрудник обычно работает только со счетами своего отделения.
    *   **Отдельные опции для критичных операций:** Для работы с резервами или конвертацией могут быть созданы специальные экраны с ограниченным функционалом.
*   **Аудит:** Ведутся журналы действий пользователей (кто, когда, что сделал). Для проводок фиксируется пользователь, введший операцию, и его отделение.
*   **Регламентные проверки:**
    *   Контроль целостности: автоматическая сверка оборотов и остатков по дебету и кредиту.
    *   Проверка соответствия проводок символам кассового плана.
*   **Обработка инцидентов:** При подозрении на ошибочную или мошенническую операцию проводится расследование с использованием журналов аудита, истории удалений, данных о пользователе.

## **РАЗДЕЛ 7: РЕГЛАМЕНТНЫЕ ПРОЦЕДУРЫ**

*   **Ежедневно:**
    *   **Закрытие операционного дня:** Самая важная процедура. Включает переоценку валютных остатков, расчёт и отражение курсовых разниц, перенос остатков на счета нового дня, формирование оборотно-сальдовой ведомости (главная книга).
    *   **Формирование и отправка обязательных отчётов** (например, кассовый отчёт).
*   **Ежемесячно/Квартально:**
    *   Формирование полного пакета бухгалтерской отчётности для ЦБ и РСБУ.
    *   Расчёт резервов на возможные потери.
*   **Взаимодействие с регуляторами:** Проверки ЦБ всегда включают анализ правильности отражения операций, особенно крупных, связанных, конверсионных. Модуль проводок — основной источник данных для таких проверок.

## **РАЗДЕЛ 8: ПРОБЛЕМНЫЕ СИТУАЦИИ И ИСКЛЮЧЕНИЯ**

*   **Типичные проблемы:**
    1.  **"Переполнение счётчика":** При массовом вводе операций (например, начисление процентов по всем вкладам) может быть исчерпан лимит на количество операций за день для одного вида. **Решение:** Использовать дополнительные технические коды для распределения нагрузки.
    2.  **Ошибка в уже закрытом дне:** **Решение:** Не вскрывать день! Создавать корректирующую проводку в текущем дне с датой учёта = дате ошибки.
    3.  **Нарушение целостности данных при интеграции:** Например, проводка прошла, а документ в системе расчетов не обновился. **Решение:** Процедуры ручной или автоматической сверки и восстановления связей.
*   **Особые случаи:**
    *   **Балкинг (групповой ввод):** Когда множество однотипных операций (например, списание комиссии с тысяч счетов) проводится одной суммой на один счёт. Экономит ресурсы, но усложняет контроль. **Важно:** В новом ПО такой подход не рекомендуется.
    *   **Операции по счетам в разных валютах:** Всегда требуют конвертации и проходят по специальным схемам.
    *   **Работа с техническими счетами:** Их номера не должны "светиться" в отчётах для клиентов и регулятора. В отчётах они автоматически заменяются на связанные с ними реальные счета.
