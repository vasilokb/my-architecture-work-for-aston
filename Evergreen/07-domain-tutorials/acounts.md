Учет счетов в банковской АБС
1. ФУНДАМЕНТ: ЧТО ТАКОЕ СЧЕТ В БАНКЕ
   1.1. Базовое определение
   Счет — это учетная запись в банковской системе, которая:
   Имеет уникальный номер
   Привязана к конкретному клиенту (физическому/юридическому лицу) или к банку
   Отражает движение денежных средств
   Имеет установленные правила использования
   1.2. Почему это сложная система
   У одного клиента может быть десятки счетов:
   В разных валютах (рубли, доллары, евро)
   Для разных целей (текущие, депозитные, кредитные)
   В разных отделениях банка
   С разными режимами работы
   Пример клиента — малого бизнеса:
   ИП Петров И.И. имеет:
1. 40702810xxxxxxxxx — расчетный счет в рублях
2. 40702840xxxxxxxxx — валютный счет в долларах
3. 40817810xxxxxxxxx — личный счет Петрова
4. 42301810xxxxxxxxx — депозит на 1 год
5. 45201810xxxxxxxxx — кредитный счет
6. 40702810yyyyyyyyy — спецсчет для госзаказов


2. СИСТЕМА НОМЕРАЦИИ: КАК РАЗОБРАТЬСЯ В 20 ЗНАКАХ
   2.1. Полная расшифровка номера счета
   Возьмем пример: 40817810700001121205
   Разбираем по цифрам:
   Позиции 1-3:  408        — счет первого порядка (привлеченные средства физлиц)
   Позиции 1-5:  40817      — счет второго порядка (физлица-резиденты)
   Позиции 6-8:  810        — код валюты (рубли)
   Позиция 9:    7          — контрольный ключ (рассчитывается по алгоритму)
   Позиции 10-13: 0000      — код отделения, где открыт счет
   Позиции 14-20: 1121205   — лицевая часть (уникальная для клиента)


2.2. Коды валют — это не только цифры
810 — российские рубли
840 — доллары США
978 — евро
156 — китайские юани
XAU — золото (буквенный код!)
XAG — серебро
Важно: Для драгметаллов код содержит буквы, что усложняет обработку.
2.3. Контрольный ключ (позиция 9)
Рассчитывается по специальной формуле ЦБ:
Берется БИК банка
Берется 20-значный номер счета
По алгоритму считается контрольная сумма
Если ключ неверный — счет технически некорректен
Проверка при открытии: Система автоматически проверяет правильность ключа.
3. ВИДЫ СЧЕТОВ: КТО ДЛЯ ЧЕГО
   3.1. Клиентские счета (самые важные)
   Для физических лиц:
   40817 — текущие счета резидентов
   40820 — текущие счета нерезидентов
   42301-42309 — депозиты (вклады) до востребования и срочные
   42601-42609 — депозиты в драгметаллах
   45501-45510 — кредитные счета
   Для юридических лиц:
   40702 — расчетные счета коммерческих организаций
   40703 — счета ИП и частных практиков
   40701 — счета бюджетных организаций
   40802 — счета нерезидентов
   42001-42009 — депозиты организаций
   3.2. Внутренние счета банка
   Доходы/расходы:
   70601 — процентные доходы
   70606 — комиссионные доходы
   70607 — доходы от операций с валютой
   70611-70613 — операционные расходы
   Технические счета:
   99998 — счета конверсии (технические)
   99999 — клиринговые счета
   Счета главы В — забалансовые счета
4. ПРОЦЕСС ОТКРЫТИЯ СЧЕТА: ПОШАГОВО
   4.1. Подготовительный этап
   Что проверяется ДО открытия:
   Проверка клиента:
   Есть ли клиент в базе? (поиск по ФИО/ИНН)
   Не находится ли в стоп-листах?
   Актуальны ли документы?
   Проверка типа счета:
   Разрешен ли этот тип счета для данного клиента?
   Например, счет 40702 нельзя открыть физическому лицу
   Проверка отделения:
   Может ли данное отделение открывать такие счета?
   Есть ли лимиты на количество счетов?
   4.2. Процедура открытия
   Шаг 1: Инициализация
   Оператор выбирает:
- Тип счета: 40817 (текущий счет физлица)
- Валюта: 810 (рубли)
- Отделение: 0001 (головное)
- Клиент: Иванов И.И. (PIN: A12345)


Шаг 2: Генерация номера Система автоматически:
Находит свободный номер в диапазоне для 40817
Генерирует 13-значный номер АБС: 0001 B67890 001
Генерирует 20-значный номер РПС: 4081781070001123456
Проверяет уникальность обоих номеров
Шаг 3: Установка параметров
Автоматически устанавливаются:
- Бухгалтерский режим: 100 (полная доступность)
- Дата открытия: текущая дата
- Ответственное подразделение: из профиля оператора
- Базовые спецусловия


Шаг 4: Дополнительные настройки Оператор вручную устанавливает:
Полное наименование счета: "Текущий счет Иванова И.И."
Лимит овердрафта: 0 (по умолчанию)
Процентную ставку: 0.01% (для остатков)
Тарифный план: "Базовый"
Шаг 5: Фиксация в реестрах
Запись в таблицу соответствия счетов (13-значный → 20-значный)
Запись в книгу регистрации счетов
Запись в историю изменений
4.3. Особые случаи при открытии
Случай 1: Валютный счет При открытии валютного счета автоматически открываются:
Основной валютный счет (40702840...)
Транзитный счет (зачисление валюты)
Специальный транзитный счет (продажа валюты)
Случай 2: Парные счета Для некоторых операций требуются два счета:
Активный (дебетовый)
Пассивный (кредитовый) Открываются одновременно, закрываются только вместе.
Случай 3: Счет с отложенным открытием Иногда счет нужно открыть "задним числом":
Проверяется, была ли такая дата в работе банка
Проверяются все операции за эту дату
Устанавливается специальный статус
5. ПАРАМЕТРЫ СЧЕТА: ЧТО МОЖНО НАСТРАИВАТЬ
   5.1. Бухгалтерские режимы (самое важное!)
   Режим 100: "Работает как часы"
   Все операции разрешены
   Стандартный режим для рабочих счетов
   Режим 200: "Можно только класть"
   Запрещены списания (дебетовые операции)
   Можно только пополнять
   Используется при блокировках по решению клиента
   Режим 300: "Частичная блокировка"
   Можно списывать только определенные суммы
   Обычно по решению суда или налоговой
   Режим 400: "Закрыт"
   Только просмотр остатков
   Никакие операции невозможны
   Предпоследний этап перед удалением
   Режим 500: "Зарезервирован"
   Технический режим
   Счет создан, но не активирован
   Используется при пакетном открытии
   Режим 800: "Полная блокировка"
   Запрещены ВСЕ операции
   Часто по решению правоохранительных органов
   5.2. Специальные условия (спецусловия)
   Базовые ограничения:
   Условие 011: Запрет кредитовых операций (нельзя пополнять)
   Условие 012: Запрет дебетовых операций (нельзя списывать)
   Условие 030: Счет в процессе закрытия
   Условие 047: Внутренний счет (не клиентский)
   Процентные настройки:
   Условие 015: Начислять проценты по дебету (за использование средств)
   Условие 016: Начислять проценты по кредиту (на остаток)
   Технические:
   Условие 082: Ограничение операций (арест)
   Условие 106: Запрет дебетового сальдо (овердрафта)
   Условие 999: Только системные проводки
   5.3. Практический пример настройки депозитного счета
   Депозит "Выгодный" на 1 год:
1. Тип счета: 42304 (срочный депозит)
2. Валюта: 810 (рубли)
3. Бухгалтерский режим: 700 (нельзя пополнять)
4. Спецусловия:
    - 015: N (не начислять проценты за использование)
    - 016: Y (начислять проценты на остаток)
    - 030: N (не закрываемый)
    - 106: Y (запрет овердрафта)
5. Процентная ставка: 8.5% годовых
6. Дата окончания: через 365 дней
7. Автопролонгация: Y (да)


6. ОПЕРАЦИИ ПО СЧЕТУ: КАК ЭТО РАБОТЕТ
   6.1. Проведение платежа
   Клиент платит 10,000 руб. за интернет:

1. Оператор вводит платежное поручение
2. Система проверяет:
    - Есть ли 10,000 руб. на счете?
    - Не заблокирован ли счет?
    - Разрешены ли списания?
    - Не превышен ли дневной лимит?
3. Если проверки пройдены:
    - Списывается 10,000 руб.
    - Формируется проводка
    - Обновляется остаток
4. Клиенту выдается чек/квитанция


6.2. Обработка овердрафта
Сценарий: На счете 5,000 руб., клиент пытается заплатить 7,000 руб.
Проверка разрешения овердрафта:
Есть ли установленный лимит овердрафта? (например, 10,000 руб.)
Не исчерпан ли он?
Если овердрафт разрешен:
Проводится операция на 7,000 руб.
Счет уходит в минус: -2,000 руб.
Начинает начисляться процент за использование
Если овердрафт запрещен:
Операция отклоняется
Клиенту сообщается "Недостаточно средств"
Предлагаются альтернативы (кредит, отложенный платеж)
6.3. Начисление процентов
Ежедневно в конце операционного дня:
Система проверяет все счета со спецусловием 016
Для каждого счета:
Берется дневной остаток
Рассчитываются проценты: Остаток × Ставка / 365
Накапливает сумму за месяц
В последний день месяца:
Все накопленные проценты проводятся на счет
Формируется проводка
Отправляется уведомление клиенту
Пример:
Счет с 1,000,000 руб. под 5% годовых:
Ежедневный процент: 1,000,000 × 0.05 / 365 = 136.99 руб.
За 30 дней: 136.99 × 30 = 4,109.70 руб.
31 числа: на счет зачисляется 4,109.70 руб.


7. ЗАКРЫТИЕ СЧЕТА: ПОЛНЫЙ ЦИКЛ
   7.1. Условия закрытия
   Обязательные условия:
   Нулевой остаток (или остаток перенесен)
   Нет неисполненных распоряжений
   Нет установленных блокировок (кроме закрывающих)
   Закрыты все связанные счета (парные, дочерние)
   7.2. Процедура закрытия
   Шаг 1: Инициирование
   Клиент пишет заявление
   Оператор проверяет условия
   Шаг 2: Блокировка
   Устанавливается бухгалтерский режим 400
   Запрещаются все новые операции
   Завершаются текущие операции
   Шаг 3: Проверка остатков
   Система проверяет:
- Основной остаток: должен быть 0
- Ожидающие поступления: должны быть обработаны
- Непроведенные операции: должны быть проведены или отменены
- Начисленные проценты: должны быть капитализированы


Шаг 4: Закрытие
Фиксируется дата закрытия
Делается запись в книге регистрации
Счет переводится в архив
Клиенту выдается справка о закрытии
Шаг 5: Архивация
Данные сохраняются в архивной базе
Сохраняется история операций (5 лет минимум)
Очищаются оперативные таблицы
7.3. Особые случаи закрытия
Случай 1: Закрытие с остатком Если на счете есть деньги:
Клиент указывает счет для перевода
Делается перевод остатка
Затем стандартная процедура закрытия
Случай 2: Принудительное закрытие По решению банка (например, неактивный счет):
Отправляется уведомление клиенту
Через 60 дней счет блокируется
Через 90 дней остаток переводится на специальный счет
Счет закрывается
Случай 3: Закрытие из-за смерти клиента
Требуется свидетельство о смерти
Остаток переводится наследникам
Требуется решение нотариуса
Особый учет в системе
8. ТЕХНИЧЕСКИЕ ОПЕРАЦИИ СО СЧЕТАМИ
   8.1. Перенос счета
   Когда нужно: Клиент переезжает в другой город, банк переводит его в другое отделение.
   Что происходит:
   Было: Счет 40817810700001121205 в отделении 0001
   Стало: Счет 40817810700051121205 в отделении 0005

Изменения:
- 13-значный номер меняется (новое отделение)
- 20-значный номер НЕ меняется (позиции 10-13 меняются)
- Все история сохраняется
- Операции продолжаются без перерыва


Техническая реализация:
Создается новый 13-значный счет
На него переносится 20-значный номер
Переносятся все параметры
Старый счет закрывается
Делается проводка переноса остатка
8.2. Перегенерация счета
Когда нужно: Нужно поменять балансовую позицию (например, 42301 → 42304).
Что происходит:
Было: 42301810700001121205 (депозит до востребования)
Стало: 42304810700001121205 (срочный депозит)

Изменения:
- 13-значный номер НЕ меняется
- 20-значный номер меняется (позиции 1-5)
- Тип счета меняется


8.3. Объединение счетов
Когда у клиента два одинаковых счета:
Проверяется возможность объединения
Остатки суммируются
Один счет закрывается
История объединяется

   МЕЖБАНКОВСКИЕ ПЕРЕВОДЫ:

2. Счетная система:
    - Открывает кредитный счет 45501

3. Ежемесячно:

    - Списывается с текущего счета
    - Зачисляется в погашение кредита


9.3. С системам отчетности
Ежедневно:
Формируется оборотно-сальдовая ведомость
Сверяются остатки по всем счетам
Проверяется соответствие балансу
Ежемесячно:
Формируются выписки для клиентов
Рассчитываются налоги (для процентов)
Формируется отчетность в ЦБ

11. ПРОБЛЕМЫ И РЕШЕНИЯ
    11.1. Типичные проблемы
    Проблема 1: "Двойная трата" Ситуация: Клиент снимает деньги в банкомате и одновременно делает платеж онлайн.
    Решение:
    Система блокирует сумму при первой операции
    Вторая операция видит заблокированные средства
    Если средств хватает — проводится
    Если нет — отклоняется
    Проблема 2: "Технический овердрафт" Ситуация: Из-за задержки в системе операции проводятся в неправильном порядке.
    Решение:
    Система ведет журнал операций
    При расхождении — автоматический пересчет
    Уведомление клиента
    Корректирующие проводки
    Проблема 3: "Потерянная операция" Ситуация: Деньги списались, но не дошли до получателя.
    Решение:
    Поиск в журналах операций
    Проверка всех промежуточных систем
    Возврат средств или ручной перевод
    Анализ причин и исправление процесса
    11.2. Контрольные вопросы для аналитика
    При проектировании спросите:
    Что делать, если два клиента претендуют на один номер счета?
    Как обрабатывать счета с отрицательной датой открытия?
    Что делать при смене типа клиента (физлицо → ИП)?
    Как архивировать счета с миллионами операций?
    Как обеспечить уникальность 20-значного номера?
12. ПРАКТИЧЕСКОЕ ЗАДАНИЕ ДЛЯ СТАЖЕРОВ
    Задание: Спроектировать систему учета депозитных счетов
    Часть 1: Структура данных
    Определите поля для хранения:
    Основных параметров счета
    Процентных ставок
    Графика выплат
    Условий досрочного закрытия
    Часть 2: Процессы 2. Опишите пошагово:
    Открытие депозита
    Ежемесячное начисление процентов
    Выплату процентов клиенту
    Пролонгацию депозита
    Досрочное закрытие
    Часть 3: Интеграции 3. Спроектируйте интеграцию с:
    Платежной системой (пополнение)
    Налоговой системой (налог на проценты)
    CRM (уведомление клиентов)
    Часть 4: Особые случаи 4. Разработайте обработку:
    Смерти вкладчика
    Судебного ареста счета
    Технических сбоев при начислении процентов
    Ожидаемый результат:
    Модель базы данных (таблицы, связи)
    Диаграммы процессов (BPMN)
    API-спецификации для интеграций
    Пользовательские сценарии (use cases)
    Тест-кейсы для проверки

Совет: Начните с самого простого — счета до востребования. Потом добавьте срочные депозиты. Затем — валютные счета. Постепенно усложняйте, добавляя проценты, комиссии, интеграции. Не пытайтесь сделать всё сразу — разбивайте на итерации.
