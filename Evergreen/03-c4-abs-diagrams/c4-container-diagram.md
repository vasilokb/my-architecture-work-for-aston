## Описание контейнеров

### 1. Входящий шлюз

#### 1.1 API Gateway

**Назначение:** Единая точка входа для всех внешних запросов к платформе.

**Основные функции:**
- Прием REST-запросов от фронтальных систем и надстроек
- Аутентификация и авторизация запросов (JWT-токены)
- Маршрутизация запросов к бизнес-модулям
- Ограничение частоты запросов (rate limiting)
- Сбор метрик и логирование
- Добавление идентификатора тенанта в контекст запроса (из токена или заголовка)

**Границы ответственности:**
- Отвечает только за прием и маршрутизацию входящих запросов
- Не содержит бизнес-логики
- Не управляет исходящими соединениями

### 2. Ядро банковской логики

#### 2.1 Модуль учета клиентов (CIF)

**Назначение:** Централизованное управление информацией о клиентах.

**Основные функции:**
- Регистрация и ведение клиентов (физические и юридические лица)
- Хранение анкетных данных, паспортной информации, контактных данных
- Хранение документов (паспорта, доверенности, учредительные документы)
- Классификация клиентов по сегментам (массовый, премиальный, VIP)
- Управление статусами клиента (активен, заблокирован, закрыт)
- Проверка клиентов по стоп-листам
- Ведение истории изменений данных клиента

**Взаимодействие:**
- Предоставляет данные о клиентах счетному модулю для открытия счетов

#### 2.2 Модуль учета счетов

**Назначение:** Управление банковскими счетами клиентов.

**Основные функции:**
- Открытие и закрытие счетов (расчетные, ссудные, депозитные, карточные)
- Управление остатками по счетам
- Блокировка и разблокировка счетов
- Ведение плана счетов (балансовые и внебалансовые счета)
- Контроль минимального остатка
- Формирование выписок по счетам
- Управление лимитами по счетам

**Взаимодействие:**
- Получает запросы на открытие счетов от кредитного, депозитного и карточного модулей
- Предоставляет данные об остатках платежному модулю
- Передает данные бухгалтерскому модулю для формирования проводок
- Принимает команды на списание от тарифного модуля и модуля ДБП

#### 2.3 Бухгалтерский модуль

**Назначение:** Учет всех банковских операций, формирование проводок.

**Основные функции:**
- Формирование бухгалтерских проводок по всем операциям
- Ведение журнала транзакций
- Управление холдами (заморозкой средств)
- Контроль двойной записи и соблюдения баланса
- Выполнение конверсионных операций (валютный обмен)
- Обеспечение целостности данных и отката транзакций

**Взаимодействие:**
- Получает запросы на формирование проводок от всех модулей
- Получает транзакции из процессинга через интеграционный модуль
- Формирует проводки по признанию дохода для модуля ДБП

### 3. Система расчетов

#### 3.1 Модуль расчетов

**Назначение:** Обработка платежных документов и маршрутизация платежей.

**Основные функции:**
- Прием и обработка платежных поручений
- Формирование реестров на платежи
- Маршрутизация платежей по типам (СБП, внутрибанковские, межбанковские)
- Управление очередями платежей
- Контроль корректности заполнения платежных документов
- Проверка остатков (через счетный модуль) и лимитов (через лимитный модуль)
- Расчет комиссий (через тарифный модуль)
- Формирование проводок (через бухгалтерский модуль)
- Передача исходящих платежей в интеграционный модуль

**Взаимодействие:**
- Получает платежные поручения через API Gateway
- Проверяет остатки в счетном модуле
- Проверяет лимиты в лимитном модуле
- Рассчитывает комиссии в тарифном модуле
- Передает исходящие платежи в интеграционный модуль
- Формирует проводки через бухгалтерский модуль

### 4. Тарифный блок

#### 4.1 Тарифный модуль

**Назначение:** Управление тарифами и расчет комиссий.

**Основные функции:**
- Хранение тарифов по всем банковским продуктам
- Поддержка типов тарифов:
  - **Периодические:** годовое обслуживание карт, ежемесячное обслуживание счетов
  - **Транзакционные:** комиссии за переводы, снятие наличных
  - **Разовые:** выпуск карт, выписки, SMS-информирование
- Поддержка тарифных пакетов (комбинированные предложения)
- Автоматический расчет комиссии в момент оказания услуги
- Формирование требований на списание комиссий
- Передача авансовых платежей в модуль ДБП

**Взаимодействие:**
- Получает запросы на расчет комиссий от платежного, карточного и кредитного модулей
- Передает требования на списание в счетный модуль
- Передает информацию о комиссиях в бухгалтерский модуль
- Передает авансовые платежи в модуль ДБП

#### 4.2 Модуль учета доходов будущих периодов (ДБП)

**Назначение:** Учет авансовых платежей и их распределение по периодам.

**Основные функции:**
- Учет авансовых платежей за периодические услуги
- Хранение информации о длительных услугах (срок действия, сумма аванса)
- Распределение суммы аванса равномерно по периодам действия услуги
- Ведение графика признания дохода (ежемесячно, ежеквартально)
- Формирование требований на списание авансов со счетов клиентов
- Формирование проводок по признанию дохода через бухгалтерский модуль
- Ведение остатков доходов будущих периодов

**Взаимодействие:**
- Получает информацию об авансовых платежах от тарифного модуля
- Формирует проводки по признанию дохода через бухгалтерский модуль
- Инициирует списание авансовых платежей через счетный модуль

### 5. Карточный блок

#### 5.1 Модуль пластиковых карт

**Назначение:** Управление жизненным циклом банковских карт (дебетовых и кредитных).

**Основные функции:**
- Управление карточными продуктами (типы карт, дизайны, тарифы)
- Выпуск и перевыпуск карт (эмбоссинг, персонализация)
- Управление ПИН-кодами (генерация, изменение, восстановление)
- Привязка карт к счетам (дебетовые) или кредитным договорам (кредитные)
- Блокировка и разблокировка карт
- Управление статусами карт (выпущена, активирована, заблокирована)
- Синхронизация карт и статусов с процессингом

**Взаимодействие:**
- Получает запросы через API Gateway
- Привязывает дебетовые карты к счету через счетный модуль
- Управляет кредитными картами через кредитный модуль (двусторонняя связь)
- Проверяет и устанавливает лимиты через лимитный модуль
- Рассчитывает комиссии через тарифный модуль
- Формирует проводки через бухгалтерский модуль
- Синхронизирует карты и статусы с процессингом через интеграционный модуль

#### 5.2 Модуль лимитов

**Назначение:** Централизованное управление лимитами и стоп-листами.

**Основные функции:**
- Настройка карточных лимитов (суточные, на операции) → синхронизация в процессинг
- Настройка платежных лимитов (СБП, межбанк) → проверка в платежном модуле
- Настройка кредитных лимитов (для кредитных карт) → синхронизация в процессинг
- Ведение стоп-листов (заблокированные карты, счета) → синхронизация в процессинг
- Проверка платежных лимитов по запросу платежного модуля
- Синхронизация с процессингом (исходящие: лимиты, стоп-листы; входящие: использованные лимиты)

**Границы ответственности:**
- **Не проверяет** карточные лимиты при авторизации (это делает процессинг)
- **Проверяет** платежные лимиты для переводов (СБП, межбанк)
- **Синхронизирует** карточные и кредитные лимиты с процессингом
- **Принимает** от процессинга информацию об использованных лимитах

**Взаимодействие:**
- Проверяет платежные лимиты по запросу платежного модуля
- Устанавливает лимиты по карте по запросу карточного модуля
- Синхронизирует лимиты и стоп-листы с процессингом через интеграционный модуль
- Получает обновления по использованным лимитам из интеграционного модуля

### 6. Кредитный блок

#### 6.1 Кредитный учет

**Назначение:** Учет выданных кредитов, начисление процентов и штрафов.

**Основные функции:**
- Учет выданных кредитов (сумма, срок, ставка, график платежей)
- Открытие ссудных счетов через счетный модуль
- Начисление процентов по графику
- Начисление штрафов и пеней при просрочке
- Учет погашений (основной долг, проценты, штрафы)
- Управление кредитными лимитами (для кредитных карт)
- Формирование проводок по кредитным операциям
- Синхронизация кредитных лимитов с процессингом

**Границы ответственности:**
- Кредитный конвейер (андеррайтинг, скоринг, принятие решений) вынесен в надстройку
- В ядре АБС только бухгалтерский учет выданных кредитов

**Взаимодействие:**
- Получает данные о выданных кредитах от кредитного конвейера (надстройка)
- Управляет кредитными картами через карточный модуль
- Открывает ссудные счета через счетный модуль
- Формирует проводки через бухгалтерский модуль
- Запрашивает кредитные истории через интеграционный модуль
- Рассчитывает комиссии через тарифный модуль
- Синхронизирует кредитные лимиты с процессингом через интеграционный модуль

---

### 7. Депозитный блок

#### 7.1 Депозитный учет

**Назначение:** Управление депозитными договорами.

**Основные функции:**
- Учет депозитных договоров (сумма, срок, ставка, условия)
- Открытие депозитных счетов через счетный модуль
- Начисление процентов по формуле (с капитализацией или без)
- Учет пополнений и частичного снятия
- Обработка досрочного расторжения с пересчетом процентов
- Автоматическая пролонгация депозита
- Формирование проводок по депозитным операциям

**Взаимодействие:**
- Открывает депозитные счета через счетный модуль
- Формирует проводки по начислению процентов через бухгалтерский модуль

---

### 8. Администрирование 

#### 8.1 Административный модуль

**Назначение:** Управление многотенантной платформой.

**Основные функции:**
- Управление тенантами (банками-клиентами):
  - Создание новых тенантов (создание схемы в БД, начальная настройка)
  - Настройка параметров тенанта (лимиты, тарифы)
  - Мониторинг использования ресурсов
- Управление пользователями платформы:
  - Создание и блокировка пользователей
  - Назначение ролей и прав доступа
- Управление ролевой моделью
- Управление биллингом и тарификацией для тенантов

**Взаимодействие:**
- Получает административные запросы через API Gateway
- Взаимодействует с интеграционным модулем для административных запросов к внешним системам

### 9. Интеграция
#### 9.1 Интеграционный модуль

**Назначение:** Управление всеми исходящими интеграциями с внешними системами.

**Основные функции:**
- Управление исходящими соединениями с внешними системами
- Адаптация протоколов (ISO8583, SWIFT, SFTP, REST)
- Трансформация форматов сообщений
- Управление очередями исходящих запросов
- Реализация retry-политик и circuit breaker
- Прием входящих данных от внешних систем
- Маршрутизация входящих данных к соответствующим модулям
- Мониторинг состояния интеграций

**Интегрируемые системы:**

| Система | Исходящие данные (АБС →) | Входящие данные (→ АБС) |
|---------|-------------------------|------------------------|
| **Процессинг** | Лимиты, стоп-листы, карты, кредитные лимиты | Транзакции, клиринговые файлы, чарджбеки, использованные лимиты |
| **СБП** | Переводы по номеру телефона | Входящие переводы, статусы |
| **Межбанк** | Межбанковские переводы, SWIFT-сообщения | Выписки, SWIFT-сообщения |
| **ЦБ РФ** | Отчетность (пруденциальная, нормативы) | Нормативные документы |
| **Кредитные бюро** | Передача кредитных историй | Запросы кредитных историй |

**Взаимодействие с внутренними модулями:**
- Получает данные для отправки от лимитного, карточного, кредитного, платежного и административного модулей
- Направляет полученные данные в бухгалтерский, лимитный, карточный и кредитный модули

## Взаимодействие контейнеров (ключевые потоки)

### Входящий поток
```
Внешние системы → API Gateway → Бизнес-модули
```

### Исходящий поток
```
Бизнес-модули → Интеграционный модуль → Внешние системы
```

### Ядро банковской логики
```
CIF → Счета → Бухгалтерия
```

### Система расчетов
```
Платежный модуль → Счета (проверка остатков)
Платежный модуль → Лимитный модуль (проверка лимитов)
Платежный модуль → Тарифный модуль (расчет комиссий)
Платежный модуль → Бухгалтерия (проводки)
Платежный модуль → Интеграционный модуль (исходящие платежи)
```

### Тарифный блок
```
Тарифный модуль → Счета (списание комиссий)
Тарифный модуль → Бухгалтерия (проводки)
Тарифный модуль → ДБП (авансовые платежи)
ДБП → Бухгалтерия (признание дохода)
ДБП → Счета (списание авансов)
```

### Карточный блок
```
Карточный модуль ↔ Кредитный модуль (кредитные карты)
Карточный модуль → Счета (привязка карт)
Карточный модуль → Лимитный модуль (лимиты)
Карточный модуль → Тарифный модуль (комиссии)
Карточный модуль → Бухгалтерия (проводки)
Карточный модуль ↔ Интеграционный модуль (синхронизация с процессингом)
Лимитный модуль ↔ Интеграционный модуль (лимиты, стоп-листы)
```

### Кредитный блок
```
Кредитный модуль ↔ Карточный модуль (кредитные карты)
Кредитный модуль → Счета (ссудные счета)
Кредитный модуль → Бухгалтерия (проводки)
Кредитный модуль → Лимитный модуль (кредитные лимиты)
Кредитный модуль → Тарифный модуль (комиссии)
Кредитный модуль ↔ Интеграционный модуль (кредитные лимиты, кредитные бюро)
Кредитный конвейер (надстройка) → Кредитный модуль
```

### Депозитный блок
```
Депозитный модуль → Счета (депозитные счета)
Депозитный модуль → Бухгалтерия (проводки)
```

### Администрирование и интеграция
```
Админ-модуль → Интеграционный модуль (административные запросы)
Бухгалтерия → Интеграционный модуль (получение транзакций из процессинга)
```
