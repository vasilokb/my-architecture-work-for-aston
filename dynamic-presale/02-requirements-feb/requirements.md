## Queue Service — компоненты + функциональные требования

| Компонент                      | Назначение                       | Функциональные требования                                                                                                                                                                                                                                                                                                                               | Входы                                | Выходы                                             | Хранилище/данные         | Примечания                                           |
| ------------------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | -------------------------------------------------- | ------------------------ | ---------------------------------------------------- |
| qs_store (Queue Store)         | Очередь job + lease              | 1) Система должна сохранять job в очередь с параметрами запуска (documentId/version/mode).<br>2) Система должна выдавать job на исполнение с блокировкой (lock/lease), чтобы избежать параллельного исполнения одного job.<br>3) Система должна хранить состояние попыток и следующую дату выполнения (для backoff).                                    | `ps_flow`, `qs_retry`, `qs_dispatch` | `db_queue`                                         | `db_queue`               | Основа для управляемой очереди без Kafka             |
| qs_limit (Concurrency Limiter) | Ограничение параллельности к LLM | 1) Система должна ограничивать количество одновременных “in-flight” job, которые делают вызов LLM.<br>2) Система должна применять backpressure (не выдавать слот, если лимит исчерпан).<br>3) Система должна позволять конфигурировать лимит параллельности.                                                                                            | `qs_dispatch`                        | decision allow/deny slot                           | конфиг/счётчики          | Критично: это не RPS, а параллельность               |

| db_user (User DB)       | Пользователи/права   | 1) Система должна хранить пользователей и их права доступа.<br>2) Система должна позволять получать права пользователя по запросу User Service.                                                                          | `user_svc`                | `user_svc`                   |
| db_process (Process DB) | Состояние процесса   | 1) Система должна хранить documentId/версии/прогресс/текущий шаг.<br>2) Система должна хранить связь documentId↔fileId/fileKey и параметры запуска версии.<br>3) Система должна позволять читать статус/прогресс для UI. | `ps_state`, `qs_dispatch` | `ps_flow`, UI через status   |
| db_queue (Queue DB)     | Очередь job          | 1) Система должна хранить job, статусы, attempt, schedule/backoff.<br>2) Система должна поддерживать lock/lease для предотвращения параллельного исполнения одного job.                                                  | `qs_store`, `qs_retry`    | `qs_dispatch`                |
| db_files (Files DB)     | Метаданные файлов    | 1) Система должна хранить fileId/fileKey, имя, тип, размер, статус файла.<br>2) Система должна (опционально) хранить extracted_text как вход для LLM.                                                                    | `fs_meta`                 | `ps_flow`, `fs_extract`      |
| db_prompt (Prompt DB)   | Пресеты и raw LLM    | 1) Система должна хранить пресеты промптов по режимам.<br>2) Система должна хранить raw ответы LLM по documentId/version/attempt для дебага.                                                                             | `prs_presets`, `prs_raw`  | `prs_builder`, анализ (refs) |
| db_result (Result DB)   | Результаты и экспорт | 1) Система должна хранить версии результата (Table 1 + Table 2 + totals).<br>2) Система должна хранить метаданные экспорта и (опц.) содержимое Excel/ссылку.                                                             | `as_repo`, `rs_store`     | `rs_access`, `rs_excel`      |
